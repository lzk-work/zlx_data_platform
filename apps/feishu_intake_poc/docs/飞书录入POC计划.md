# 飞书录入 POC 验证计划

本文用于约束第一个飞书录入到数据库闭环验证。POC 只验证链路可信，不追求字段完整。

## 1. 验证目标

验证以下方向是否可行：

```text
业务人员在飞书录入记录
  -> Python 通过飞书 API 拉取待处理记录
  -> Python 做基础校验和字段标准化
  -> 写入数据库 ODS 表和 biz 表
  -> Python 将入库结果、错误信息、数据库 ID 回写飞书
```

如果该闭环跑通，后续再扩展到产品主档、SKU、货源、图片、上架资料等正式流程。

## 2. 建议 Demo 范围

先只选一个业务环节：

```text
产品开发录入
```

先只选一张飞书多维表格：

```text
产品开发 Demo 表
```

建议只处理：

```text
业务状态 = 开发完成
同步状态 = 未同步 / 同步失败 / 空
```

暂不处理：

- 复杂附件下载
- 多表关联字段
- 人员字段解析
- 飞书表间自动流转
- 复杂动态类目规则
- 正式 SKU 编码生成
- 定时任务和生产部署

## 3. 飞书 Demo 字段

### 业务录入字段

| 字段名 | 类型 | 是否必填 | 说明 |
|---|---|---:|---|
| 开发时间 | 日期 | 是 | 产品开发完成或提交日期 |
| 开发代号 | 文本 | 是 | 开发阶段临时编号 |
| 商品SKU | 文本 | 是 | 先用手填或临时 SKU 验证 |
| 来源平台 | 单选 | 是 | Amazon、Ozon、Walmart 等 |
| 变体码 | 文本 | 是 | 同一商品下的变体标识 |
| ID/ASIN | 文本 | 否 | 平台商品 ID |
| 一级类目（通用） | 单选/文本 | 是 | 通用类目 |
| 二级类目（通用） | 单选/文本 | 是 | 通用类目 |
| 三级类目（通用） | 单选/文本 | 否 | 通用类目 |
| 采购价格 | 数字 | 是 | 用于验证数值类型 |
| 重量-g | 数字 | 否 | 用于验证数值类型 |
| 货源链接 | URL/文本 | 否 | 用于验证链接字段 |
| 备注 | 多行文本 | 否 | Demo 备注 |

### 业务状态和回写字段

| 字段名 | 建议类型 | 说明 |
|---|---|---|
| 业务状态 | 单选 | 草稿、待提交、开发完成、已作废 |
| 校验状态 | 单选 | 未校验、校验通过、校验失败 |
| 同步状态 | 单选 | 未同步、已入库、同步失败、已回写 |
| 错误信息 | 多行文本 | API 回写 |
| 数据库ID | 文本/数字 | biz 表主键 ID |
| ODS_ID | 文本/数字 | ODS 原始记录 ID |
| 同步批次ID | 文本 | 一次同步任务的批次号 |
| 入库时间 | 日期时间 | 成功入库时间 |
| 最近同步时间 | 日期时间 | 最近一次处理时间 |

## 4. 程序职责拆分

POC 代码建议按职责拆成 5 层：

```text
client
  只负责外部系统：飞书 API 或 mock 数据。

mapper
  只负责字段翻译：飞书中文字段 -> 内部英文字段。

validator
  只负责业务校验：必填、枚举、数字范围、唯一性预检。

repository
  只负责数据库：ODS 原始表、biz 标准表、同步映射表。

runner
  只负责流程编排：读取、判断、校验、入库、回写、报告。
```

这样后续新增“货源录入”“图片资产录入”“上架资料录入”时，可以复用飞书 client、数据库写入思路和流程编排模式。

## 5. 最小校验规则

| 字段 | 规则 |
|---|---|
| 开发时间 | 必填，能转换成日期 |
| 商品SKU | 必填，去空格后不能为空 |
| 来源平台 | 必填，必须在允许枚举内 |
| 变体码 | 必填 |
| 一级类目（通用） | 必填 |
| 二级类目（通用） | 必填 |
| 采购价格 | 如填写，必须为数字且大于等于 0 |
| source_platform + product_sku + variant_code | 唯一 |

校验失败建议仍写 ODS 或错误日志，但不进入 biz 标准表。

## 6. API 能力验证点

至少验证：

| 能力 | 用途 |
|---|---|
| 获取 tenant_access_token | 服务端应用鉴权 |
| 查询多维表格记录 | 拉取业务录入数据 |
| 更新多维表格记录 | 回写校验状态和入库结果 |
| 分页读取 | 验证记录量增长后的基础能力 |
| record_id 识别 | 确认飞书记录与数据库记录能稳定关联 |

## 7. 验收标准

### 正常记录

准备 1 条完整记录：

```text
业务状态 = 开发完成
同步状态 = 未同步
```

运行后应看到：

```text
ODS 表新增或更新 1 条记录
biz 表新增或更新 1 条记录
飞书回写：校验通过、已入库、数据库ID、入库时间
```

### 异常记录

准备 1 条缺少 SKU 或采购价格非法的记录。

运行后应看到：

```text
biz 表不新增
飞书回写：校验失败、同步失败、错误信息
```

### 重复运行

同一批数据连续运行 2 次。

预期：

```text
不会重复插入同一条记录
ODS 和 biz 通过唯一键 upsert
飞书状态保持稳定
```

### 修改后重跑

在飞书修改同一条记录的采购价格或备注，再运行脚本。

预期：

```text
数据库记录被更新
raw_payload 保留最新飞书快照或按策略保留
飞书最近同步时间刷新
```

## 8. 推荐执行顺序

```text
1. 在飞书创建 Demo 表和字段
2. 创建飞书应用，配置多维表格权限
3. 将应用添加为多维表格协作者
4. 本地准备 env 配置
5. 建 demo ODS、biz、sync 表
6. 实现同步脚本
7. 用正常、异常、草稿、重复运行样例验证
8. 整理日志和问题清单
9. 决定是否迁移到正式产品开发表
```

## 9. 关键判断

Demo 成功的标准不是字段完整，而是链路可信。

如果 Demo 跑通，说明：

- 飞书可以承担轻量业务录入。
- Python 可以稳定读取、校验和回写。
- 数据库可以作为事实存储与状态中心。
- 后续可以把产品主档、货源、图片、上架等环节拆成多张飞书表，但统一经过数据库流转。
