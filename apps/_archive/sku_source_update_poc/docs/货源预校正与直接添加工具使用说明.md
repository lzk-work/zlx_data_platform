# 货源预校正与直接添加工具使用说明

## 1. 工具用途

本工具用于出单前的货源处理，不生成 ERP 新增表或 ERP 更新表。

它支持两种模式：

```text
platform：已上架平台 SKU 货源预校正
source-only：直接添加货源
```

共同规则：

- 先用清洗后的 `货源链接 + 规格` 查询商品基础库。
- 查到唯一商品 SKU：复用该商品 SKU。
- 查不到：生成新商品 SKU，并插入 `zlx_1.product_source`。
- 查到多个：进入异常。
- 不更新已有商品 SKU 的货源信息。

商品基础库来自数据库：

```text
zlx_1.product_source
```

一级类目编码来自数据库：

```text
zlx_1.first_category_code
```

## 2. 两种模式怎么选

使用 `platform` 模式：

- 已有平台 SKU。
- 想提前校正平台 SKU 对应的货源。
- 需要输出平台 SKU 与商品 SKU 的映射关系。

使用 `source-only` 模式：

- 没有平台 SKU。
- 只是想把一批新货源先加入商品基础库。
- 已存在的货源直接跳过。

## 3. 目录位置

APP 目录：

```text
apps/sku_source_update_poc
```

配置文件：

```text
apps/sku_source_update_poc/config/settings.example.yaml
```

输入目录：

```text
apps/sku_source_update_poc/data/input
```

输出目录：

```text
apps/sku_source_update_poc/data/output
```

每次运行会在输出目录下生成一个批次文件夹：

```text
apps/sku_source_update_poc/data/output/YYYYMMDD_HHMMSS
```

## 4. 输入文件

平台 SKU 货源预校正模板：

```text
apps/sku_source_update_poc/data/input/平台SKU货源预校正输入表.xlsx
```

直接添加货源模板：

```text
apps/sku_source_update_poc/data/input/直接添加货源输入表.xlsx
```

当前配置文件通过 `paths.input` 指定实际读取的输入文件。

切换模式时，需要确认 `settings.example.yaml` 里的 `paths.input` 指向对应模板或正式输入文件。

注意：当前代码读取器要求两种模式的输入表都至少包含以下四个表头：

```text
平台SKU
初始商品SKU
校正后货源链接
校正后规格
```

`source-only` 模式下，`平台SKU` 和 `初始商品SKU` 可以为空，但表头需要保留。

## 5. platform 模式输入字段

平台 SKU 货源预校正输入表字段：

```text
平台SKU
初始商品SKU
校正后货源链接
校正后规格
一级类目
类目代号
图片链接
采购价/￥
重量/g
长/cm
宽/cm
高/cm
颜色
材质
数量
中文报关名
供应商
备注
```

说明：

- `平台SKU` 必填。
- `初始商品SKU` 只作为参考字段。
- 最终商品 SKU 由 `校正后货源链接 + 校正后规格` 查询结果决定。
- 如果货源已存在，输出平台 SKU 映射关系，不新增商品基础库。
- 如果货源不存在，生成新商品 SKU，新增商品基础库，并输出平台 SKU 映射关系。

## 6. source-only 模式输入字段

直接添加货源输入表字段：

```text
平台SKU
初始商品SKU
校正后货源链接
校正后规格
一级类目
类目代号
图片链接
采购价/￥
重量/g
长/cm
宽/cm
高/cm
颜色
材质
数量
中文报关名
供应商
备注
```

说明：

- 不需要填写平台 SKU，但表头需要保留。
- 不需要填写初始商品 SKU，但表头需要保留。
- 如果货源已存在，跳过。
- 如果货源不存在，生成新商品 SKU，并新增商品基础库。
- 不输出平台 SKU 映射关系。

## 7. 数据库连接

运行前需要设置数据库连接环境变量：

```powershell
$env:SKU_SOURCE_UPDATE_DATABASE_URL="postgresql://user:password@host:5432/database"
```

不要把真实密码写入文档或提交到代码仓库。

## 8. 执行前检查

platform 模式检查：

```powershell
python -m apps.sku_source_update_poc.src.main --config apps\sku_source_update_poc\config\settings.example.yaml --mode platform --check
```

source-only 模式检查：

```powershell
python -m apps.sku_source_update_poc.src.main --config apps\sku_source_update_poc\config\settings.example.yaml --mode source-only --check
```

检查内容包括：

- 输入表是否存在。
- 输入表字段是否符合当前模式要求。
- 数据库是否能连接。
- `product_source` 是否能读取。
- `first_category_code` 是否能读取。

## 9. 试运行

platform 模式试运行：

```powershell
python -m apps.sku_source_update_poc.src.main --config apps\sku_source_update_poc\config\settings.example.yaml --mode platform --dry-run
```

source-only 模式试运行：

```powershell
python -m apps.sku_source_update_poc.src.main --config apps\sku_source_update_poc\config\settings.example.yaml --mode source-only --dry-run
```

试运行只生成输出文件，不写数据库。

## 10. 正式运行

platform 模式正式运行：

```powershell
python -m apps.sku_source_update_poc.src.main --config apps\sku_source_update_poc\config\settings.example.yaml --mode platform
```

source-only 模式正式运行：

```powershell
python -m apps.sku_source_update_poc.src.main --config apps\sku_source_update_poc\config\settings.example.yaml --mode source-only
```

正式运行规则：

- 正常行：把本次新增商品 SKU 插入 `zlx_1.product_source`。
- 异常行：跳过，不写数据库，只进入异常表和日志。
- `--dry-run`：不写数据库。

## 11. 输出文件

批次输出目录示例：

```text
apps/sku_source_update_poc/data/output/20260725_140108
```

主要输出：

```text
本次商品基础库新增表.xlsx
本次平台SKU映射关系表.xlsx
异常待处理表.xlsx
处理日志表.xlsx
```

说明：

- `本次商品基础库新增表.xlsx`：本次准备插入数据库的新商品 SKU。
- `本次平台SKU映射关系表.xlsx`：platform 模式输出的平台 SKU 与商品 SKU 映射关系。
- `异常待处理表.xlsx`：需要人工修正后重跑的数据。
- `处理日志表.xlsx`：记录成功行和异常行。

source-only 模式下，平台 SKU 映射关系表通常为空。

## 12. SKU 生成规则

新商品 SKU 格式：

```text
一级类目编码_YYMMDD_当日递增序号
```

示例：

```text
YS_260708_1
YS_260708_2
JK_260708_1
```

递增序号按当天日期和类目分别计算，不取全局最大值。

## 13. 重跑规则

如果只是试运行：

- 删除不需要的 output 批次目录即可。
- 修正输入表后重新执行。

如果正式运行有异常：

- 正常行会照常写入数据库。
- 异常行不会写入数据库。
- 修正异常行后，可以放到下一批重新执行。

如果正式运行无异常后再次执行同一批数据：

- 已存在的货源会被识别出来。
- platform 模式会重新输出映射关系。
- source-only 模式会跳过已存在货源。

## 14. 常见异常

常见异常包括：

- platform 模式下平台 SKU 为空。
- 校正后货源链接为空或清洗失败。
- 校正后规格为空。
- 商品基础库中同一个 `货源链接 + 规格` 匹配到多个商品 SKU。
- 新增商品 SKU 时缺少一级类目或类目编码。

异常行不会写入数据库，也不会输出平台 SKU 映射关系。正常行不受异常行影响。

## 15. 与出单管理工具的区别

本工具只处理货源和映射预校正，不生成 ERP 表。

出单后需要生成 ERP 新增表、ERP 更新表，并滚动维护已上传、历史出单、映射状态时，使用：

```text
apps/sku_mapping_poc
```
