# 商品 SKU 管理当前设计状态

更新时间：2026-07-30

当前模块仍处于需求调整阶段，暂不编码。本文档用于维护当前设计快照，避免历史迭代中已废弃的信息继续影响后续设计和开发。

## 1. 已确定需求

### 1.1 当前优先级

```text
第一版优先开发：已上架平台 SKU 数据补充清洗。
新开发产品正向流程作为后续扩展，暂不作为第一版编码目标。
```

第一版目标：

```text
整理已有上架数据。
补齐平台SKU对应的真实货源结构。
识别销售单元，并确定映射目标类型和映射目标SKU。
生成或匹配商品SKU、组合SKU。
建立平台SKU到内部映射目标的关系。
输出店小秘导入模板。
输出店小秘导出动作计划。
保留处理批次、逐行日志、异常表和映射快照。
```

### 1.2 商品 SKU 口径

```text
商品SKU是库存最小单位。
商品SKU不代表销售单元。
商品SKU不表达销售数量。
商品SKU一定先匹配或生成。
商品SKU生成规则沿用旧规则，但含义改为库存最小单位。
```

采购侧套装口径：

```text
判断商品SKU时看采购侧，不看销售侧。
1688 加购 1 件是什么，商品SKU就代表什么。
1688 单个规格是一件单品 -> 商品SKU。
1688 单个规格是一套预包装套装 -> 商品SKU。
多个 1688 规格组合成一个销售产品 -> 组合SKU。
同一个 1688 规格销售数量 > 1 -> 组合SKU。
```

### 1.3 销售单元口径

```text
销售单元是逻辑对象，不是另一种 SKU 产物。
开发SKU和平台SKU都是销售单元在不同阶段的业务标识。
开发SKU代表开发阶段的销售单元。
平台SKU代表上架后的销售单元。
系统不单独新增第三套销售单元业务编码。
销售单元可以有内部记录ID，但业务流转使用开发SKU、平台SKU、映射目标类型和映射目标SKU。
```

映射目标规则：

```text
单品销售单元：映射目标类型 = 商品SKU，映射目标SKU = 商品SKU。
组合/多件销售单元：映射目标类型 = 组合SKU，映射目标SKU = 组合SKU。
```

### 1.4 平台 SKU 口径

```text
平台SKU由上架端生成。
平台SKU唯一键使用平台SKU本身。
平台SKU编写规则：平台简称_店铺简称_开发代号_单店铺内产品序号。
每个销售单元只要上架，就不会出现重复平台SKU。
即使同一销售单元在同一店铺上架多次，也会生成不同平台SKU。
平台渠道、店铺账号保留为辅助字段，用于展示、校验和追溯。
```

### 1.5 输入规格格式

```text
业务输入货源数据格式：完整货源链接 + 规格 + 货源备注。
货源链接必须是完整可访问链接，例如 https://detail.1688.com/offer/1006973663950.html?offerId=1006973663950&hotSaleSkuId=6171378627344&spm=a260k.home2025.recommendpart.3。
不允许只填 111.html、offer/111.html 或其他残缺链接。
货源链接清洗只负责去掉不必要参数并统一标准格式，例如清洗为 https://detail.1688.com/offer/1006973663950.htm。
规格格式：参数1||参数2||参数3||数量。
数量永远放在最后。
最后一个 || 后面的数字是数量。
最后一个 || 前面的内容是 1688 规格文本。
多个产品使用外层中文括号分割。
只有整段规格完全由连续括号明细组成时，才按多个产品拆分。
如果括号只是 1688 规格文本的一部分，不拆分。
```

货源链接N + 货源N规格 + 货源N备注 + 货源N采购价 + 货源N重量/kg：一组货源输入。

第一版补数据输入字段以本节字段清单为准。英文报关名系统不生成，业务后续在导出模板中人工翻译回填；销售标题和其他未明确店小秘字段第一版不作为必填输入，导出时按空值处理。

### 1.7 字段归属

已确认：开发录入和补数据流程的前半段都以销售单元为单位。

```text
开发SKU代表开发阶段销售单元。
平台SKU代表上架后的销售单元。
商品SKU是系统根据销售单元的货源结构拆分出来的库存/采购最小单位。
映射目标SKU用于说明销售单元最终指向商品SKU还是组合SKU。
```

开发信息字段归属：

```text
主图链接、销售标题、销售图片、销售数量、重量/g、长/cm、宽/cm、高/cm、颜色、材质、中文报关名、英文报关名、开发备注、动态字段等，首先都属于开发SKU/销售单元的竞品上架参考信息。
这些字段给运营和业务参考使用，最终字段清单需要对标竞品开发表后再确定。
```

商品 SKU 字段归属：

```text
商品SKU主表保留库存/采购最小单位的身份字段、当前主货源指向，以及店小秘商品SKU模板需要的中文报关名、参考采购价和参考重量。
商品SKU不默认承载开发录入的销售标题、销售图片、长宽高、颜色、材质等销售单元字段。中文报关名按店小秘商品SKU字段处理，可从销售单元输入同步到商品SKU主表。
中文报关名来自开发SKU/平台SKU销售单元输入；参考采购价、参考重量不是销售单元字段原样搬运，而是根据货源组采购价、货源重量和规格数量拆分计算得到。
这些值用于店小秘商品SKU模板、采购参考和申报参考，属于可计算参考值/估算值，不作为绝对准确采购主数据。
```

商品 SKU 主表建议暂保留：

```text
商品SKU

当前主货源链接
当前主规格
货源图片链接
供应商
一级类目

参考采购价RMB
参考重量g
中文报关名
备注

```

商品 SKU 主表和商品 SKU 货源表都可保留参考采购价和参考重量：

```text
当前输入按货源链接分组给出信息，例如：
货源链接1、货源1规格、货源1备注、货源1采购价、货源1重量/kg。

系统可以根据规格中的数量，反推单个商品SKU的参考采购价和参考重量。
单个产品：参考采购价 = 货源采购价 / 数量；参考重量 = 货源重量 / 数量。
多个产品：按每个货源分组的总采购价和总重量，结合该组内数量计算平均参考采购价和平均参考重量。

该结果只是参考值/估算值，不作为绝对准确采购主数据。
字段命名应体现 reference/estimated，例如：参考采购价、参考重量。
```
单位标准化规则：

```text
业务输入货源重量单位：kg。
数据库重量字段单位：g。
店小秘商品净重、申报重量单位：g。
系统处理时必须先将业务输入重量 kg * 1000 转换为 g，再参与商品SKU平均重量、组合SKU总重量和店小秘模板输出。
业务输入采购价单位：RMB，不做单位换算。
店小秘采购参考价单位：RMB，直接使用计算后的平均采购价。
店小秘申报金额单位：USD，按采购价 / 6.8 计算。
```
数据库字段单位设计：

```text
product_sku.reference_purchase_price_rmb：当前主货源计算出的商品SKU参考采购价，单位 RMB。
product_sku.reference_weight_g：当前主货源计算出的商品SKU参考重量，单位 g。
product_sku.chinese_customs_name：商品SKU中文报关名，用于店小秘商品SKU模板和报关信息。
product_sku_source.reference_purchase_price_rmb：该货源计算出的商品SKU参考采购价，单位 RMB。
product_sku_source.reference_weight_g：该货源计算出的商品SKU参考重量，单位 g。
sales_unit.total_purchase_price_rmb：销售单元总采购价，单位 RMB。
sales_unit.total_weight_g：销售单元总重量，单位 g。
```

写入规则：

```text
业务输入的货源N重量/kg 不直接入库。
系统清洗后先换算为 g，再写入 product_sku.reference_weight_g、product_sku_source.reference_weight_g 或 sales_unit.total_weight_g。
业务输入的货源N采购价按 RMB 处理，不做币种换算。
```
### 1.8 商品 SKU 货源关系

采用双表设计：

```text
product_sku：商品SKU主表，保持一行一个商品SKU，保存当前主货源。
product_sku_source：商品SKU货源表，保存当前货源、备用货源、历史货源。
```

已确认：

```text
同一个商品SKU可以有多个货源。
商品SKU主表不因为备用货源变成一对多。
第一版正常只使用一个主货源。
备用货源现在只做未来预留，不参与第一版处理流程、自动采购配对、平台SKU映射、查找替换或主货源切换。
主货源切换能力后续再设计，第一版不实现。
组合SKU不直接绑定采购货源，采购关系来自子商品SKU。
```

### 1.9 商品 SKU 变体码

```text
开发SKU变体码是人工标记，只用于前端/开发侧识别一组开发销售单元。
商品SKU变体码不直接沿用开发SKU变体码。
商品SKU变体码由系统生成历史唯一的新码。
开发SKU变体组只是过程态来源。
商品SKU变体码需要支持集合合并。
集合合并时保留库内最早已有的商品SKU变体码。
```

记录要求：

```text
product_sku_variant_merge_record：长期保存被合并变体码 -> 最终变体码。
product_sku_variant_merge_log：记录每次归并处理日志。
```

人工覆盖：

```text
人工指定最终保留变体码后续通过接口预留。
第一版不实现人工覆盖自动判断。
```


### 1.10 店小秘导入模板填充口径

已确认：第一版需要输出店小秘商品 SKU 模板、组合 SKU 模板和平台 SKU 配对模板。英文报关名等字段暂不由系统翻译，业务批量翻译后直接在导出文档中复制回填。

商品 SKU 模板填充口径：

```text
*SKU(必填)：商品SKU
中文名称：按规格参数生成，详见“中文名称生成规则”
图片URL：统一使用开发SKU/平台SKU销售单元的主图链接
商品净重（g）：业务输入货源重量为 kg，系统先换算为 g，再按货源组采购重量和规格数量计算得来的平均重量
采购参考价（RMB）：按货源组采购价和规格数量计算得来的平均采购价
来源URL：货源链接
备注：商品SKU模板取对应的货源N备注；该备注同时写入商品SKU主表 note 和商品SKU货源表 note
中文报关名：商品SKU模板使用商品SKU主表的中文报关名；新建商品SKU时由开发SKU/平台SKU销售单元输入同步生成
申报重量(g)：业务输入货源重量为 kg，系统换算为 g 后计算得来的平均重量
申报金额（USD）：计算得来的平均采购价 / 6.8
英文报关名：系统暂不处理；业务批量翻译后直接在导出文档中复制回填，不预留系统回填接口
其他未明确字段：第一版统一留空
```

组合 SKU 模板填充口径：

```text
*组合sku：组合SKU
中文名称：按规格参数生成，详见“中文名称生成规则”
组合SKU主图URL：统一使用开发SKU/平台SKU销售单元的主图链接
包含的商品sku：组合明细中的子商品SKU
数量：组合明细中的子商品数量
中文报关名：使用开发SKU/平台SKU销售单元的中文报关名
申报重量(g)：开发SKU/平台SKU销售单元总重；业务输入货源重量为 kg，系统换算为 g 后计算；多个货源组时按货源组重量求和
申报金额（USD）：开发SKU/平台SKU销售单元总采购价 / 6.8；多个货源组时按货源组采购价求和后除以 6.8
英文报关名：系统暂不处理；业务批量翻译后直接在导出文档中复制回填，不预留系统回填接口
其他未明确字段：第一版统一留空
```


中文名称生成规则：

```text
基础规则：将规格中的参数连接符 || 替换为 /，并在最后追加 *产品数量。
商品SKU中文名称：规格参数1/规格参数2/...*产品数量。
单个产品无需添加其他说明。
多个产品/组合产品中的每个子商品SKU，仍按单个商品规则生成中文名称。
组合SKU中文名称：产品总数 个/组，规格参数1/规格参数2/...*产品数量，规格参数1/规格参数2/...*产品数量，...
```

示例：

```text
商品SKU：白色/均码*1
商品SKU：中筒灰底白面/XL码（9-13岁）建议脚长20-25cm*5
组合SKU：3 个/组，白色/均码*1，肤色/均码*1，黑色/均码*1
```
平台 SKU 配对模板填充口径：

```text
*SKU(必填)：映射目标SKU，可以是商品SKU或组合SKU
平台SKU：一个或多个平台SKU；多个值用换行符拼接
```


店小秘 SKU 字符限制与系统保守规则：

```text
已查本地店小秘帮助文档：商品SKU支持英文字母 A-Z/a-z、数字 0-9、英文空格，以及常见英文半角符号。
本地文档未看到明确长度上限。
系统生成的商品SKU、组合SKU、商品SKU变体码不使用完整支持字符集，而采用保守字符集：大写英文字母、数字、下划线。
当前商品SKU规则“一级类目编码_YYMMDD_当日递增序号”和组合SKU规则“ZH_日期_商品SKU数量_产品总数_当日流水号”均满足保守字符集。
```

商品SKU变体码生成规则已确认：

```text
格式：VT_YYMMDD_SEQ
示例：VT_260730_1005
含义：VT 固定前缀 + 日期 + 数据库全局递增序列号。
优点：历史唯一、可体现生成日期、人工可读、字符集保守。
并发执行时，依赖数据库 sequence 生成全局递增序号，保证历史唯一；序号不要求连续。
```

关于雪花算法：

```text
雪花算法适合生成内部全局唯一数字ID，也能按时间递增。
但它对业务人员不直观，且通常需要机器ID/节点ID设计。
本工具的商品SKU变体码已确认使用“日期 + 数据库 sequence”的可读编码；底层内部ID未来如有需要可另用 snowflake/ULID。
```
### 1.11 编码规则

商品 SKU 编码已确认沿用旧规则。业务入参需要提供一级类目，系统根据一级类目匹配类目代号后生成商品SKU：

```text
一级类目编码_YYMMDD_当日递增序号
```

其中“当日递增序号”为商品SKU全局日流水，不按一级类目分别计数。也就是说，同一天所有一级类目共用一个 `product_sku + YYMMDD` 编码计数器。

组合 SKU 编码：

```text
ZH_日期_商品SKU数量_产品总数_当日流水号
```

示例：

```text
ZH_260729_1_3_1
ZH_260729_2_3_7
```

### 1.12 店小秘同步状态、新建/更新判定和人工维护

已确认：店小秘导入要区分“系统内部当前态”和“店小秘已上传/已确认状态”，不能默认生成模板后即代表店小秘已经成功同步。

店小秘平台 SKU 配对模板按映射目标 SKU 输出：

```text
*SKU = 映射目标SKU
平台SKU = 该映射目标SKU下的全部平台SKU，多个用换行符拼接
```

因此，系统内部必须长期维护完整平台 SKU 映射关系：

```text
platform_sku_mapping = 当前系统认定的全部平台SKU -> 映射目标SKU关系
```

当某个已有商品SKU或组合SKU新增一个平台SKU映射时，店小秘配对模板不能只输出新增平台SKU，而必须输出该映射目标SKU当前全部平台SKU集合。

第一版采用三层状态：

```text
内部当前态：
product_sku、product_sku_source、bundle_sku、bundle_sku_item、sales_unit、platform_sku_mapping

店小秘同步状态：
dianxiaomi_sync_state

本批导出动作计划：
dianxiaomi_export_plan
```

`dianxiaomi_sync_state` 记录店小秘侧最近一次已确认状态，允许业务人工维护：

```text
object_type：product_sku / bundle_sku / platform_pair
object_key：商品SKU / 组合SKU / 映射目标SKU
sync_status：not_synced / exported / confirmed / manually_synced / stale / failed
last_export_batch_id
last_export_action：create / update / skip / manual_review
last_export_hash
last_confirmed_hash
last_exported_at
last_confirmed_at
manual_note
```

其中 `platform_pair` 的 `object_key` 使用映射目标 SKU，而不是单个平台SKU，因为店小秘配对模板更新的是“映射目标SKU -> 全部平台SKU集合”。

`dianxiaomi_export_plan` 记录每个批次每个对象本次应如何导出：

```text
process_batch_id
object_type：product_sku / bundle_sku / platform_pair
object_key：商品SKU / 组合SKU / 映射目标SKU
action_type：create / update / skip / manual_review
reason
current_hash
previous_hash
payload_json
export_file
```

新建/更新判定：

```text
sync_state 不存在或没有 last_confirmed_hash -> create
sync_state 存在且 current_hash = last_confirmed_hash -> skip
sync_state 存在且 current_hash != last_confirmed_hash -> update
平台SKU已存在但映射目标不同 -> manual_review 或异常，不自动覆盖
```

人工维护适配：

```text
如果业务已在店小秘/ERP手工建好或改好数据，可手动维护 dianxiaomi_sync_state。
只要 last_confirmed_hash 更新为系统当前计算出的 current_hash，下一批即可判定为 skip。
如果之后系统当前态再次变化，current_hash 与 last_confirmed_hash 不一致，则重新生成 update。
```

推荐上传顺序保持不变：

```text
1. 商品SKU create/update
2. 组合SKU create/update
3. 平台SKU配对 create/update
```

第一版不调用店小秘 API，不自动确认上传成功。导出模板和动作计划只说明本批应该创建、更新、跳过或人工复核什么，最终上传结果由业务人工上传后维护 `dianxiaomi_sync_state`。
