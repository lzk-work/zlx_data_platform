# 商品 SKU 管理重构设计草案

## 1. 设计目标

本次重构不是在旧 POC 上改字段，而是重建商品 SKU 的底层数据结构，使其适配店小秘的库存、采购、组合 SKU 和平台 SKU 配对逻辑。

设计时需要提前兼容飞书录入模块，但第一版优先做“已上架平台 SKU 数据补充清洗”。先把已有平台 SKU、货源、商品 SKU、组合 SKU 和店小秘配对关系整理干净，并留下可追溯记录。正向开发流程后续再接入飞书多维表格：开发人员填写竞品开发信息、长宽高、货源信息和动态字段，系统通过 API 获取数据，完成流转校验和入库。

新工具要脱离旧 POC 的核心假设：

```text
旧思路：商品SKU 可以代表一个平台销售单位
新思路：商品SKU 只代表库存最小单位
```

最终目标：

```text
第一版优先：
已上架平台SKU补数据 -> 解析货源 -> 商品SKU/组合SKU -> 平台SKU映射 -> 店小秘配对模板 -> ERP/店小秘可用

后续扩展：
飞书竞品开发数据 -> 开发SKU销售单元 -> 商品SKU/组合SKU -> 给运营上架

上架后闭环：
平台SKU + 映射目标类型 + 映射目标SKU -> 店小秘配对模板 -> ERP/店小秘可用
```

## 2. 核心定义

### 2.1 销售单元

销售单元是销售视角的产品表达。

开发 SKU 和平台 SKU 都是销售单元标识，但处在不同阶段。

```text
开发SKU：开发人员参考竞品信息形成的销售单元标识。
平台SKU：运营上架到公司店铺后形成的平台销售单元标识。
```

开发 SKU 不代表库存最小单位，也不直接参与采购库存。

平台 SKU 同样不代表库存最小单位，也不表达数量。

二者都需要经过销售单元拆解，落到：

```text
商品SKU
组合SKU
组合SKU明细
```

开发阶段填写的长宽高、销售图片、标题、颜色、材质、报关名、动态字段等，首先属于开发SKU对应销售单元的竞品上架参考信息，不属于商品 SKU。

销售单元是开发信息流转到运营上架的核心关联对象。

```text
开发人员录入的信息 -> 生成销售单元
销售单元 -> 回写开发信息
运营上架 -> 使用销售单元中的销售参数和映射目标SKU
```

运营上架不需要直接使用商品 SKU 明细。

```text
商品SKU用于采购、库存、1688配对。
销售单元用于上架、销售参数、平台SKU生成和平台SKU映射。
```

销售单元不再单独生成第三套业务编码。

```text
单品销售单元：销售单元业务编码 = 商品SKU
组合/多件销售单元：销售单元业务编码 = 组合SKU
```

因此开发信息回写和运营上架使用的编码，就是最终映射目标 SKU。

上架后的闭环：

```text
业务/运营根据销售单元完成上架
  -> 生成平台SKU
  -> 回传 平台SKU + 映射目标类型 + 映射目标SKU
  -> 系统生成店小秘平台SKU配对模板
  -> 导入店小秘
  -> ERP/店小秘后续可根据平台SKU识别对应货源和库存单位
```

### 2.2 商品 SKU

商品 SKU 是库存最小单位。

固定口径：

```text
商品SKU = 单一产品 = 完整清洗后货源链接 + 规格 + 数量1
```

商品 SKU 不再表达：

```text
同款2件
同款3件
A产品 + B产品
套装
多件装
```

这些由组合 SKU 表达。

例外口径已确认：

```text
如果 1688 货源本身就是套装规格，采购时购物车 +1 就代表采购一套，
则该套装是一个采购侧最小单位，可以作为普通商品SKU。
```

判断标准：

```text
看采购侧，不看销售侧。
1688 加购 1 件是什么，商品SKU就代表什么。
```

因此：

```text
1688 单个规格 = 一件单品 -> 商品SKU
1688 单个规格 = 一套预包装套装 -> 商品SKU
多个 1688 规格组合成一个销售产品 -> 组合SKU
同一个 1688 规格销售数量 > 1 -> 组合SKU
```

商品 SKU 也不再承载销售侧参数。

以下字段不放在商品 SKU 表：

```text
长/cm
宽/cm
高/cm
颜色
材质
英文报关名
开发备注
```

这些字段属于平台 SKU 对应的销售单元，用于店小秘刊登、平台配对或销售资料维护，应放在销售单元层。中文报关名是例外：输入来源仍来自销售单元，但店小秘内部也将其视为商品SKU字段，平台SKU直接映射商品SKU时需要从商品SKU取值，因此商品SKU主表也保存中文报关名。

商品 SKU 需要支持商品 SKU 变体码。

```text
商品SKU变体码 = 从商品SKU视角标记一组可作为变体集合的商品SKU
```

它不同于开发 SKU 中的变体码。

```text
开发SKU变体码：开发人员在竞品开发阶段标记的一组销售单元集合。
商品SKU变体码：销售单元拆解后，从库存最小单位角度重新赋予的一组商品SKU变体集合。
```

### 2.3 组合 SKU

组合 SKU 表达销售组合，不直接代表一个独立采购货源。

组合 SKU 明细：

```text
组合SKU
子商品SKU
子商品数量
```

典型场景：

```text
同款2件装：
组合SKU RED-L-2PCS
  -> RED-L x2

多商品套装：
组合SKU SET-A
  -> RED-L x1
  -> BLUE-M x1
```

### 2.4 平台 SKU

平台 SKU 是平台销售端 SKU。

平台 SKU 可以映射到：

```text
普通商品SKU
组合SKU
```

平台 SKU 不直接参与采购和库存。

平台 SKU 与商品 SKU 只是配对关系，不表达数量。

```text
平台SKU -> 商品SKU
```

只能表示这个平台 SKU 配对到这个商品 SKU，不能表示：

```text
平台SKU -> 商品SKU x 2
```

如果平台 SKU 销售数量大于 1，必须通过组合 SKU 表达。

平台 SKU 不是所有流程的前置条件。

```text
新开发产品阶段：通常还没有平台SKU。
已上架补数据阶段：通常已有平台SKU、平台渠道、店铺账号。
```

因此系统需要同时支持两个方向：

```text
新开发：先识别开发SKU对应的销售单元，再确定映射目标SKU，供运营上架使用。
补数据：用已有平台SKU识别销售单元，并补齐映射目标SKU、货源和采购配对。
```

### 2.5 商品 SKU 货源关系

商品 SKU 主表只保存当前主货源，用于保持原系统一行一个商品 SKU 的稳定结构。

商品 SKU 的全部货源链接和规格，单独存储在商品 SKU 货源表中。

```text
商品SKU主表：当前主货源
商品SKU货源表：当前货源 + 备用货源 + 历史货源
```

货源关系绑定商品 SKU，不绑定平台 SKU，也不绑定组合 SKU。

采购关系至少包含：

```text
商品SKU
货源平台
货源链接
货源规格
供应商
参考采购价RMB
参考重量g
货源状态
是否主货源
备注
```

第一版业务只使用一个主货源。备用货源仅作为未来能力预留，不参与第一版处理流程、自动采购配对、平台 SKU 映射、查找替换或主货源切换。

主货源切换能力后续再设计，第一版不实现。
## 3. 新数据模型

### 3.1 商品 SKU 基础表

表语义：库存最小单位。

建议逻辑表名：

```text
product_sku
```

核心字段：

```text
商品SKU
商品SKU变体码
货源链接
规格
货源图片链接
供应商
一级类目
类目代号
参考采购价RMB
参考重量g
中文报关名
备注
创建时间
最后更新时间
```

唯一性：

```text
货源链接 + 规格
```

数量字段说明：

```text
商品SKU自身数量固定为1。
商品SKU表不保留销售数量。
如果采购侧存在整包采购、按盒采购，需要另建采购包装/采购换算字段，不进入商品SKU身份。
```

字段归属原则：

```text
商品SKU表解决：这是什么库存最小单位、当前主货源是什么，以及店小秘商品SKU模板需要的中文报关名、参考采购价和参考重量。
开发录入的销售展示、包装尺寸、颜色材质等字段不属于商品SKU表。中文报关名按店小秘商品SKU字段处理，需要在商品SKU主表保存。
中文报关名可以由开发SKU/平台SKU销售单元输入同步到商品SKU主表；参考采购价和参考重量可以写入商品SKU主表，但必须来自货源组采购价、货源重量和规格数量的拆分计算。
商品SKU主表中的参考采购价和参考重量用于店小秘商品SKU模板、采购参考和申报参考，属于可计算参考值/估算值，不作为绝对准确采购主数据。
```

商品 SKU 变体码口径已确认：

```text
同一组可作为变体集合的商品SKU，拥有同一个商品SKU变体码。
商品SKU变体码在销售单元拆解后生成。
商品SKU变体码不直接等同于开发SKU变体码。
商品SKU变体码必须历史唯一。
一旦库内已存在某个商品SKU变体码，该变体码不应被废弃或复用到无关集合。
```

商品 SKU 变体码的来源有两种：

```text
人工标记：开发时，业务将不同开发SKU标记为同一开发SKU变体组。
代码梳理：程序将开发SKU变体组拆解为商品SKU集合后，形成商品SKU变体组。
```

人工标记的开发 SKU 变体组中，不同开发 SKU 的货源链接可以不一致。

程序处理时，开发 SKU 变体码只是过程态集合标识。真正入库前，需要通过货源链接和规格匹配库内商品 SKU，并完成商品 SKU 变体码归并。

### 3.2 组合 SKU 主表

表语义：销售组合单位。

建议逻辑表名：

```text
bundle_sku
```

核心字段：

```text
组合SKU
组合名称
组合类型
备注
创建时间
最后更新时间
```

组合类型建议：

```text
same_product_multi_qty
multi_product_set
prepacked_set
manual
```

组合 SKU 编码规则已确认：

```text
ZH_日期_商品SKU数量_产品总数_当日流水号
```

示例：

```text
ZH_260729_1_3_1
```

字段含义：

```text
ZH：组合 SKU 固定前缀
260729：日期，格式 YYMMDD
1：组合中不同商品 SKU 的数量
3：组合中的产品总数，即所有子商品数量求和
1：当日流水号，不补零
```

更多示例：

```text
同款 3 件装：
组合SKU = ZH_260729_1_3_1
组合明细 = 商品SKU A x3

两种商品共 3 件：
组合SKU = ZH_260729_2_3_2
组合明细 = 商品SKU A x1 + 商品SKU B x2
```

### 3.3 组合 SKU 明细表

表语义：组合 SKU 拆解关系。

建议逻辑表名：

```text
bundle_sku_item
```

核心字段：

```text
组合SKU
子商品SKU
子商品数量
备注
```

唯一性：

```text
组合SKU + 子商品SKU
```

### 3.4 销售单元表

表语义：内部准备给运营上架或已经用于销售的销售表达。

销售单元可以指向：

```text
商品SKU
组合SKU
```

建议逻辑表名：

```text
sales_unit
```

核心字段：

```text
销售单元SKU
销售单元来源
开发SKU
开发SKU变体码
销售单元类型
映射目标类型
映射目标SKU
销售标题
销售数量
销售图片
销售单元总采购价RMB
销售单元总重量g
长/cm
宽/cm
高/cm
颜色
材质
中文报关名
英文报关名
开发批次
开发来源
飞书记录ID
动态字段JSON
开发备注
创建时间
最后更新时间
```

销售单元来源：

```text
development
platform_listing
manual
```

销售单元类型：

```text
single_product
same_product_multi_qty
multi_product_set
prepacked_set
manual
```

字段归属原则：

```text
开发SKU/平台SKU代表销售单元；开发录入字段首先属于开发SKU对应销售单元的竞品上架参考信息。
新开发产品没有平台SKU时，先生成销售单元。
运营上架后，再用平台SKU映射到该销售单元。
飞书动态字段进入开发信息/销售单元记录，使用结构化 JSON 或扩展字段保留。具体字段最终对标竞品开发表。
```

开发到上架的流转规则：

```text
新开发产品处理完成后，必须生成商品SKU或组合SKU，并回写开发信息。
运营上架时使用映射目标SKU和销售参数。
运营不需要商品SKU采购明细。
上架后生成平台SKU，再建立 平台SKU -> 销售单元 的映射。
```

销售单元是否需要单独编码：

```text
不需要。
销售单元可以有内部主键，但不生成独立业务编码。
业务流转使用 映射目标类型 + 映射目标SKU。
```

### 3.5 平台 SKU 映射表

表语义：平台销售 SKU 到内部销售单元的映射。

建议逻辑表名：

```text
platform_sku_mapping
```

核心字段：

```text
平台SKU
平台渠道
店铺账号
销售单元SKU
绑定来源
绑定时间
最后更新时间
备注
```

平台 SKU 映射表本身不再直接承载销售参数。销售参数在 `sales_unit`。

上架补数据时，如果输入中包含新的销售参数，应更新或创建销售单元，再建立平台 SKU 到销售单元的映射。

店小秘最终导入时，需要将销售单元翻译为：

```text
平台SKU -> 商品SKU
平台SKU -> 组合SKU
```

唯一性已确认：

```text
平台SKU唯一。平台SKU已存在且映射目标一致时视为幂等成功；平台SKU已存在但映射目标不一致时进入异常，不自动覆盖。
```

字段归属原则：

```text
平台SKU映射表只表示“哪个平台SKU绑定哪个销售单元”。属性是销售单元字段，用于出单后选择物流，不属于商品SKU。
同一个销售单元可以被多个平台、多个店铺、多个平台SKU复用。
同一个商品SKU也可以派生出多个销售单元。
```

平台 SKU 编写规则已确认：

```text
平台简称_店铺简称_开发代号_单店铺内产品序号
```

示例：

```text
USW_ZL0_ZLX_026
```

含义：

```text
USW：平台简称
ZL0：店铺简称
ZLX：开发代号
026：单店铺内产品序号
```

业务口径：

```text
平台SKU由上架端给出。
每个销售单元只要上架，就不会出现重复平台SKU。
即使同一销售单元在同一店铺上架多次，也会生成不同平台SKU。
平台SKU自身可作为唯一键。
平台渠道、店铺账号仍保留为辅助字段，用于展示、校验和追溯。
```

### 3.6 商品 SKU 货源表

表语义：记录每个商品 SKU 的全部可用、曾用或备用货源。

该表用于兼容未来备用货源能力，但不改变商品 SKU 主表的一行一 SKU 结构。

建议逻辑表名：

```text
product_sku_source
```

核心字段：

```text
商品SKU
货源平台
货源链接
货源规格
供应商
参考采购价RMB
参考重量g
货源状态
是否主货源
备注
创建时间
最后更新时间
```

货源状态建议：

```text
active：当前可用货源
inactive：已停用货源
candidate：候选备用货源，预留状态，第一版不参与处理
```

货源级参考采购价和参考重量说明：

```text
当前输入按货源链接分组给出信息，例如：
货源链接1、货源1规格、货源1备注、货源1采购价、货源1重量/kg。

系统可以根据规格中的数量，反推单个商品SKU的参考采购价和参考重量。
单个产品：参考采购价 = 货源采购价 / 数量；参考重量 = 货源重量 / 数量。
多个产品：按每个货源分组的总采购价和总重量，结合该组内数量计算平均参考采购价和平均参考重量。

该结果只是参考值/估算值，不作为绝对准确采购主数据。
字段命名应体现 reference/estimated，例如：参考采购价、参考重量。
```
单位标准化规则：

```text
业务输入货源重量单位：kg。
数据库重量字段单位：g。
店小秘商品净重、申报重量单位：g。
系统处理时必须先将业务输入重量 kg * 1000 转换为 g，再参与商品SKU平均重量、组合SKU总重量和店小秘模板输出。
业务输入采购价单位：RMB，不做单位换算。
店小秘采购参考价单位：RMB，直接使用计算后的平均采购价。
店小秘申报金额单位：USD，按采购价 / 6.8 计算。
```
数据库字段命名建议：

```text
product_sku.reference_purchase_price_rmb：当前主货源计算出的商品SKU参考采购价，单位 RMB。
product_sku.reference_weight_g：当前主货源计算出的商品SKU参考重量，单位 g。
product_sku.chinese_customs_name：商品SKU中文报关名，用于店小秘商品SKU模板和报关信息。
product_sku_source.reference_purchase_price_rmb：该货源计算出的商品SKU参考采购价，单位 RMB。
product_sku_source.reference_weight_g：该货源计算出的商品SKU参考重量，单位 g。
sales_unit.total_purchase_price_rmb：销售单元总采购价，单位 RMB。
sales_unit.total_weight_g：销售单元总重量，单位 g。
```

写入规则：

```text
业务输入的货源N重量/kg 不直接入库。
系统清洗后先换算为 g，再写入 product_sku.reference_weight_g、product_sku_source.reference_weight_g 或 sales_unit.total_weight_g。
业务输入的货源N采购价按 RMB 处理，不做币种换算。
```
唯一性建议：

```text
货源平台 + 货源链接 + 货源规格
```

业务约束：

```text
商品SKU主表中的货源 = 当前主货源。
product_sku_source 中允许同一个商品SKU出现多行。
第一版正常只有一条 active + 是否主货源 = 是。
未来允许同一个商品SKU有多条 active 备用货源，但最多只能有一条主货源。
```

主货源更新规则：

```text
第一版不实现主货源切换。
未来需要启用备用货源时，再设计从 product_sku_source 选择备用货源并同步回 product_sku 主表的流程。
```

### 4.0 第一版优先级：已上架平台 SKU 补数据

第一版先开发补充历史已上架数据的能力，目标是让已有数据变干净、可追溯、可持续维护。

优先原因：

```text
  -> 输出店小秘导入模板
  -> 输出批次留档、逐行日志、异常表、映射快照
```

```text
逐行处理日志：记录每个平台SKU走到的处理分支、匹配/生成结果、异常原因。
```

关键口径：

### 4.2 商品 SKU 变体码归并规则

商品 SKU 变体码必须由系统生成，且必须历史唯一。

开发 SKU 变体码不直接作为商品 SKU 变体码。

```text
开发SKU变体码：开发人员人工标记，用于前端识别一组开发销售单元。
商品SKU变体码：系统生成，用于库存最小单位层面的商品变体集合。
```

过程态：

```text
开发SKU变体组 -> 商品SKU变体候选组 -> 系统生成/归并后的商品SKU变体码
```

例如开发 SKU 变体码为 `AAA`，程序只把 `AAA` 当作开发侧人工分组线索。最终商品 SKU 变体码不沿用 `AAA`，而是由系统生成历史唯一的新码，或在匹配到库内已有商品 SKU 变体码时归并到已有码。

建议新增商品 SKU 变体码记录表：

```text
product_sku_variant_group
```

核心字段：

```text
商品SKU变体码
生成来源
来源开发SKU变体码
创建时间
最后更新时间
备注
```

商品SKU变体码已确认采用 `VT_YYMMDD_SEQ`，例如 `VT_260730_1005`。该格式由固定前缀、日期和数据库全局递增序列号组成，历史唯一，且人工可读。并发执行时，唯一性不依赖程序内计数，而依赖数据库 sequence/identity；商品SKU变体码字段必须加唯一约束，若插入冲突则事务回滚并重新取号重试。sequence 是数据库中只会递增的取数器，不要求连续，但保证并发取号不重复。

处理步骤：

```text
1. 按开发SKU变体组聚合开发销售单元。
2. 解析每个销售单元的完整货源链接 + 规格 + 数量。
3. 对候选组内的货源链接和规格去重统计。
4. 用完整清洗后货源链接 + 规格匹配库内商品SKU。
5. 根据匹配到的库内商品SKU是否已有商品SKU变体码，决定最终商品SKU变体码。
6. 将本批新增商品SKU和匹配到的无变体码商品SKU加入最终变体组。
7. 对库内需要补变体码或迁移变体码的商品SKU执行更新。
8. 记录变体码合并记录和处理日志。
```

分支规则：

```text
匹配到一个或多个库内商品SKU，且这些商品SKU都没有商品SKU变体码：
  -> 系统生成一个历史唯一的新商品SKU变体码
  -> 将匹配到的无变体码商品SKU加入该变体组
  -> 本批新增商品SKU也使用该变体码

匹配到一个或多个库内商品SKU，且其中已有商品SKU变体码：
  -> 执行集合合并
  -> 保留库内最早已有的商品SKU变体码作为最终变体码
  -> 本次不生成新的最终变体码；如过程中生成过候选码，不入库为正式码

同时匹配到有商品SKU变体码和无商品SKU变体码的商品SKU：
  -> 先对已有变体码执行集合合并，确定最终变体码
  -> 再将无变体码商品SKU加入最终变体组
  -> 新增商品SKU也使用最终变体码

未匹配到任何库内商品SKU：
  -> 系统生成一个历史唯一的新商品SKU变体码
  -> 本批新增商品SKU全部加入该变体组
```

集合合并规则：

```text
如果匹配到多个已有商品SKU变体码：
  -> 查询这些变体码的历史顺序
  -> 若变体码本身可判断顺序，保留最早的变体码
  -> 若变体码本身不可判断顺序，按 product_sku_variant_group.创建时间 保留最早的变体码
  -> 其他变体码对应的商品SKU全部迁移到最终变体码
  -> 保留被合并变体码到最终变体码的历史映射记录
  -> 记录本次合并日志
```

事务原则：

```text
同一个开发SKU变体组的商品SKU变体码归并必须作为一个事务处理。
不能出现同一候选组内部分商品SKU使用新码、部分商品SKU仍保留旧码的割裂状态。
```

需要保留两类记录：

```text
product_sku_variant_merge_record：保留被合并变体码 -> 最终变体码的长期历史映射。
product_sku_variant_merge_log：记录每次处理批次中的合并动作、原因、涉及商品SKU和处理结果。
```

人工指定最终保留变体码的能力后续通过接口预留，第一版不实现人工覆盖自动判断。

变体码合并记录表核心字段：

```text
被合并变体码
最终变体码
合并批次
合并原因
创建时间
备注
```

变体码合并日志表核心字段：

```text
处理批次
来源开发SKU变体码
系统生成候选商品SKU变体码
最终变体码
被合并变体码
涉及商品SKU
合并原因
处理结果
创建时间
备注
```

系统需要支持两个方向。

方向 A：新开发产品。

```text

  -> 必要时系统查/建组合SKU
  -> 记录开发SKU对应销售单元
  -> 确定映射目标类型和映射目标SKU
  -> 系统生成商品SKU变体码
  -> 映射目标类型和映射目标SKU回写开发信息

  -> 导入店小秘，ERP/店小秘可用
```

方向 B：已上架产品补数据。

```text
业务已有平台SKU、平台渠道、店铺账号

  -> 系统查/建组合SKU
  -> 系统识别/记录销售单元

```

因此，平台 SKU 字段在新开发入口中不是必填，在补数据入口中必填。

### 4.4 业务输入格式

业务给出的货源数据格式为：

```text
完整货源链接 + 规格 + 货源备注
```

其中 `货源链接` 必须是完整可访问链接，系统只做规范化清洗，不根据残缺片段补全链接。`111.html`、`offer/111.html` 这类值应判为异常。

1688 链接清洗示例：

```text
输入：https://detail.1688.com/offer/1006973663950.html?offerId=1006973663950&hotSaleSkuId=6171378627344&spm=a260k.home2025.recommendpart.3
输出：https://detail.1688.com/offer/1006973663950.htm
```

其中 `规格` 是可解析结构。

规格格式：

```text
参数1||参数2||参数3||数量
```

规则：

```text
1688 产品参数有几个写几个。
数量永远放在最后。
最后一个 || 后面的数字表示数量。
最后一个 || 前面的全部内容表示 1688 规格文本。
```

单个产品示例：

```text
白色||均码||1
中筒灰底白面||XL码（9-13岁）建议脚长20-25cm||5
3.2cm葱粉星星10个装（opp袋）||2
```

多个产品使用外层括号分割：

```text
（白色||均码||1）（肤色||均码||1）（黑色||均码||1）
```

解析后得到：

```text
白色||均码，数量1
肤色||均码，数量1
黑色||均码，数量1
```

解析原则：

```text
只有整段规格完全由连续括号明细组成时，才按多个产品拆分。
如果括号只是 1688 规格文本的一部分，不拆分。
```

### 4.5 商品 SKU、组合 SKU、销售单元判定规则

解析规格后，必须先逐条查/建商品 SKU。

```text
每一条 完整清洗后货源链接 + 规格文本
  -> 匹配或生成一个商品SKU
```

商品 SKU 生成规则已确认沿用原规则：

```text
一级类目编码_YYMMDD_当日递增序号
```

生成新商品SKU时，输入行必须提供一级类目；系统通过一级类目匹配类目代号。如果该行未匹配到已有商品SKU，且一级类目为空或无法匹配类目代号，则不能生成商品SKU，应进入异常。

只是商品 SKU 的内容变为库存最小单位，不再承载销售单元字段。

平台 SKU 最终映射规则：

```text
解析后只有 1 条明细，且数量 = 1
  -> 平台SKU 映射 商品SKU

解析后只有 1 条明细，但数量 > 1
  -> 平台SKU 映射 组合SKU
  -> 组合SKU 明细：商品SKU x 数量

解析后有多条明细
  -> 平台SKU 映射 组合SKU
  -> 组合SKU 明细：每条商品SKU x 对应数量
```

销售单元生成规则：

```text
解析后只有 1 条明细，且数量 = 1
  -> 销售单元指向商品SKU

解析后只有 1 条明细，但数量 > 1
  -> 先生成组合SKU
  -> 销售单元指向组合SKU

解析后有多条明细
  -> 先生成组合SKU
  -> 销售单元指向组合SKU
```

平台 SKU 映射规则：

```text
如果输入有平台SKU
  -> 平台SKU映射到销售单元

如果输入没有平台SKU
  -> 只生成销售单元，不生成平台SKU映射
```

正向开发流转规则：

```text
新开发阶段没有平台SKU也可以完整生成销售单元。
销售单元必须有稳定的映射目标SKU，供运营上架使用。
上架信息中应带有商品SKU或组合SKU。
上架后平台SKU生成，业务回传平台SKU和映射目标SKU，再生成店小秘配对模板。
货源映射在销售单元生成时已经存在，不依赖上架动作。
```

核心结论：

```text
商品SKU一定先存在。
数量不进入商品SKU身份。
平台SKU和商品SKU只是配对关系，不能代表有几个商品SKU。
只要数量 > 1，就需要组合SKU。
只要有多条产品明细，就需要组合SKU。
```

组合 SKU 生成时：

```text
商品SKU数量 = 组合明细中不同商品SKU的数量
产品总数 = 组合明细中所有子商品数量求和
当日流水号 = 当天生成的第 N 个组合SKU，不补零
```

### 4.6 输入侧不再默认生成商品 SKU 映射

旧 POC 的核心动作是：

```text
平台SKU + 校正货源 -> 商品SKU
```

新工具必须先识别销售单元：

```text
平台SKU 对应的是单品？
平台SKU 对应的是同款多件？
平台SKU 对应的是多商品套装？
平台SKU 对应的是已预包装套装？
```

再决定映射目标：

```text
单品 -> 商品SKU
同款多件 -> 组合SKU
多商品套装 -> 组合SKU
1688 本身就是套装规格，采购购物车 +1 即一套 -> 商品SKU
```

### 4.7 单品流程

```text
输入平台SKU + 一级类目 + 完整校正后货源链接 + 校正后规格
  -> 解析出一条货源明细，数量 = 1
  -> 查商品SKU基础表
      -> 匹配到唯一商品SKU：平台SKU映射到商品SKU
      -> 未匹配：创建商品SKU，再映射
      -> 匹配多个：异常
  -> 创建或复用销售单元，销售单元指向商品SKU
  -> 如果输入有平台SKU，则平台SKU映射到销售单元
```

### 4.8 同款多件流程

```text
输入平台SKU + 一级类目 + 完整校正后货源链接 + 校正后规格 + 销售数量N
  -> 解析出一条货源明细，数量 = N
  -> 查/建商品SKU，商品SKU代表单件
  -> 查/建组合SKU
  -> 组合SKU明细 = 商品SKU x N
  -> 创建或复用销售单元，销售单元指向组合SKU
  -> 如果输入有平台SKU，则平台SKU映射到销售单元
```

### 4.9 多商品套装流程

```text
输入平台SKU + 一个或多个货源链接 + 多个规格明细
  -> 解析出多条货源明细，每条明细有独立规格文本和数量
  -> 每个货源明细查/建商品SKU
  -> 查/建组合SKU
  -> 组合SKU明细 = 多个 商品SKU x 数量
  -> 创建或复用销售单元，销售单元指向组合SKU
  -> 如果输入有平台SKU，则平台SKU映射到销售单元
```

### 4.10 商品 SKU 货源维护流程

```text
商品SKU
  -> 主表保存当前主货源
  -> 商品SKU货源表保存全部货源链接和规格
```

第一版处理流程：

```text
输入完整货源链接 + 规格
  -> 第一版只按当前主货源参与商品SKU匹配
  -> 命中：返回商品SKU
  -> 未命中：按业务输入和编码规则生成或确认商品SKU
  -> product_sku_source 仅为未来备用货源能力预留，不参与第一版自动匹配和主货源切换
```

组合 SKU 不直接做 1688 采购配对。组合 SKU 的采购关系来自其子商品 SKU。

### 4.11 店小秘 SKU 字符规则

已查本地店小秘帮助文档：商品SKU支持英文字母 A-Z/a-z、数字 0-9、英文空格，以及常见英文半角符号。本地文档未看到明确长度上限。

系统生成规则采用更保守的字符集：

```text
大写英文字母
数字
下划线
```

因此第一版生成的商品SKU、组合SKU、商品SKU变体码避免中文、空格、全角符号和特殊符号，降低导入失败风险。
## 5. 输出设计

店小秘导入模板已经给出并完成初步字段映射。第一版按当前模板输出以下几类文件。

### 5.1 商品 SKU 新增/更新表

用于导入店小秘商品管理。第一版只填已确认字段，英文报关名等字段由业务后续批量翻译，不在系统内处理。

填充口径：

```text
*SKU(必填)：商品SKU
中文名称：按规格参数生成，详见“中文名称生成规则”
图片URL：统一使用开发SKU/平台SKU销售单元的主图链接
商品净重（g）：业务输入货源重量为 kg，系统先换算为 g，再按货源组采购重量和规格数量计算得来的平均重量
采购参考价（RMB）：按货源组采购价和规格数量计算得来的平均采购价
来源URL：货源链接
备注：商品SKU模板取对应的货源N备注；该备注同时写入商品SKU主表 note 和商品SKU货源表 note
中文报关名：商品SKU模板使用商品SKU主表的中文报关名；新建商品SKU时由开发SKU/平台SKU销售单元输入同步生成
申报重量(g)：业务输入货源重量为 kg，系统换算为 g 后计算得来的平均重量
申报金额（USD）：计算得来的平均采购价 / 6.8
英文报关名：系统暂不处理；业务批量翻译后直接在导出文档中复制回填，不预留系统回填接口
其他未明确字段：第一版统一留空
```

计算说明：

```text
商品SKU是库存最小单位，输出到店小秘商品SKU模板时使用单个商品SKU的参考平均重量和参考平均采购价。
如果销售单元来自多件或多货源组合，商品SKU层只取拆分后该子商品的平均参考值，不使用销售单元总值。
```

### 5.2 组合 SKU 新增/更新表

用于导入店小秘组合 SKU。组合 SKU 表达销售单元，金额和重量使用销售单元整体口径。

填充口径：

```text
*组合sku：组合SKU
中文名称：按规格参数生成，详见“中文名称生成规则”
组合SKU主图URL：统一使用开发SKU/平台SKU销售单元的主图链接
包含的商品sku：组合明细中的子商品SKU
数量：组合明细中的子商品数量
中文报关名：使用开发SKU/平台SKU销售单元的中文报关名
申报重量(g)：开发SKU/平台SKU销售单元总重；业务输入货源重量为 kg，系统换算为 g 后计算；多个货源组时按货源组重量求和
申报金额（USD）：开发SKU/平台SKU销售单元总采购价 / 6.8；多个货源组时按货源组采购价求和后除以 6.8
英文报关名：系统暂不处理；业务批量翻译后直接在导出文档中复制回填，不预留系统回填接口
其他未明确字段：第一版统一留空
```

组合明细输出规则：

```text
一个组合SKU可以包含多个商品SKU。
店小秘组合SKU模板按明细行输出：首行承载组合SKU主信息和第一条子商品SKU，后续行继续填写同一组合SKU下的子商品SKU和数量。
```


中文名称生成规则：

```text
基础规则：将规格中的参数连接符 || 替换为 /，并在最后追加 *产品数量。
商品SKU中文名称：规格参数1/规格参数2/...*产品数量。
单个产品无需添加其他说明。
多个产品/组合产品中的每个子商品SKU，仍按单个商品规则生成中文名称。
组合SKU中文名称：产品总数 个/组，规格参数1/规格参数2/...*产品数量，规格参数1/规格参数2/...*产品数量，...
```

示例：

```text
商品SKU：白色/均码*1
商品SKU：中筒灰底白面/XL码（9-13岁）建议脚长20-25cm*5
组合SKU：3 个/组，白色/均码*1，肤色/均码*1，黑色/均码*1
```
### 5.3 平台 SKU 配对表

用于导入店小秘平台 SKU 配对。

业务回传或系统内部生成数据：

```text

映射目标类型
映射目标SKU
```

系统按映射目标类型生成店小秘导入模板：

```text

平台SKU -> 组合SKU
```

填充口径：

```text
*SKU(必填)：映射目标SKU，可以是商品SKU或组合SKU
平台SKU：一个或多个平台SKU；多个值用换行符拼接
```

导入店小秘后，ERP/店小秘即可根据平台 SKU 识别对应货源、库存单位和采购配对。

## 6. 异常处理原则

工具必须支持持续运行。

```text
正常行继续处理
异常行跳过并输出异常表
异常行修正后可放入下一批继续处理
```

异常类型初稿：

```text
平台SKU为空
销售单元类型无法判断
货源链接为空、残缺或清洗失败
规格为空
商品SKU匹配到多个
组合SKU明细为空
组合SKU明细重复
组合SKU编码无法生成
商品SKU编码无法生成
平台SKU已绑定不同目标
平台SKU补数据入口缺少平台SKU
新开发入口误填平台SKU但未指定处理方式
商品SKU变体码合并冲突
商品SKU变体码历史顺序无法判断
同一候选变体组内匹配结果不完整
```
