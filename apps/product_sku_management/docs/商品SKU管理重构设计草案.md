# 商品 SKU 管理重构设计草案

## 1. 设计目标

本次重构不是在旧 POC 上改字段，而是重建商品 SKU 的底层数据结构，使其适配店小秘的库存、采购、组合 SKU 和平台 SKU 配对逻辑。

新工具要脱离旧 POC 的核心假设：

```text
旧思路：商品SKU 可以代表一个平台销售单位
新思路：商品SKU 只代表库存最小单位
```

最终目标：

```text
平台SKU
  -> 销售单元
      -> 商品SKU x 数量
      -> 或组合SKU -> 子商品SKU x 数量
```

## 2. 核心定义

### 2.1 商品 SKU

商品 SKU 是库存最小单位。

固定口径：

```text
商品SKU = 单一产品 = 货源链接 + 规格 + 数量1
```

商品 SKU 不再表达：

```text
同款2件
同款3件
A产品 + B产品
套装
多件装
```

这些由组合 SKU 表达。

商品 SKU 也不再承载销售侧参数。

以下字段不放在商品 SKU 表：

```text
长/cm
宽/cm
高/cm
颜色
材质
中文报关名
英文报关名
销售备注
```

这些字段属于平台 SKU 对应的销售单元，用于店小秘刊登、申报、平台配对或销售资料维护，应放在平台 SKU 映射关系层。

### 2.2 组合 SKU

组合 SKU 表达销售组合，不直接代表一个独立采购货源。

组合 SKU 明细：

```text
组合SKU
子商品SKU
子商品数量
```

典型场景：

```text
同款2件装：
组合SKU RED-L-2PCS
  -> RED-L x2

多商品套装：
组合SKU SET-A
  -> RED-L x1
  -> BLUE-M x1
```

### 2.3 平台 SKU

平台 SKU 是平台销售端 SKU。

平台 SKU 可以映射到：

```text
普通商品SKU
组合SKU
```

平台 SKU 不直接参与采购和库存。

### 2.4 1688 采购配对

1688 采购配对绑定商品 SKU，不绑定平台 SKU，也不绑定组合 SKU。

采购关系至少包含：

```text
商品SKU
1688货源链接
1688规格
供应商
是否默认货源
采购价
```

## 3. 新数据模型

### 3.1 商品 SKU 基础表

表语义：库存最小单位。

建议逻辑表名：

```text
product_sku
```

核心字段：

```text
商品SKU
货源链接
规格
货源图片链接
采购价
供应商
一级类目
类目代号
备注
创建时间
最后更新时间
```

唯一性：

```text
货源链接 + 规格
```

数量字段说明：

```text
商品SKU自身数量固定为1。
商品SKU表不保留销售数量。
如果采购侧存在整包采购、按盒采购，需要另建采购包装/采购换算字段，不进入商品SKU身份。
```

字段归属原则：

```text
商品SKU表只解决：这是什么库存最小单位，从哪里采购。
销售展示、包装尺寸、颜色材质、报关信息，不属于商品SKU表。
```

### 3.2 组合 SKU 主表

表语义：销售组合单位。

建议逻辑表名：

```text
bundle_sku
```

核心字段：

```text
组合SKU
组合名称
组合类型
备注
创建时间
最后更新时间
```

组合类型建议：

```text
same_product_multi_qty
multi_product_set
prepacked_set
manual
```

### 3.3 组合 SKU 明细表

表语义：组合 SKU 拆解关系。

建议逻辑表名：

```text
bundle_sku_item
```

核心字段：

```text
组合SKU
子商品SKU
子商品数量
备注
```

唯一性：

```text
组合SKU + 子商品SKU
```

### 3.4 平台 SKU 映射表

表语义：平台销售 SKU 到店小秘配对对象的映射。

建议逻辑表名：

```text
platform_sku_mapping
```

核心字段：

```text
平台SKU
平台渠道
店铺账号
映射目标类型
映射目标SKU
销售标题
销售数量
销售图片
重量/g
长/cm
宽/cm
高/cm
颜色
材质
中文报关名
英文报关名
绑定来源
绑定时间
最后更新时间
备注
```

映射目标类型：

```text
product_sku
bundle_sku
```

唯一性待确认：

```text
平台SKU
```

或：

```text
平台渠道 + 店铺账号 + 平台SKU
```

字段归属原则：

```text
平台SKU映射表不仅表示“配对到谁”，也承载该平台销售单元的销售参数。
同一个商品SKU在不同平台SKU下，可以有不同标题、图片、申报信息、长宽高或颜色描述。
```

### 3.5 1688 采购配对表

表语义：商品 SKU 到 1688 货源规格的采购关系。

建议逻辑表名：

```text
product_sku_purchase_source
```

核心字段：

```text
商品SKU
货源平台
货源链接
货源规格
供应商
采购价
是否默认货源
备注
创建时间
最后更新时间
```

唯一性建议：

```text
商品SKU + 货源平台 + 货源链接 + 货源规格
```

## 4. 处理流程设计

### 4.1 输入侧不再默认生成商品 SKU 映射

旧 POC 的核心动作是：

```text
平台SKU + 校正货源 -> 商品SKU
```

新工具必须先识别销售单元：

```text
平台SKU 对应的是单品？
平台SKU 对应的是同款多件？
平台SKU 对应的是多商品套装？
平台SKU 对应的是已预包装套装？
```

再决定映射目标：

```text
单品 -> 商品SKU
同款多件 -> 组合SKU
多商品套装 -> 组合SKU
预包装独立库存 -> 商品SKU 或 组合SKU，需业务确认
```

### 4.2 单品流程

```text
输入平台SKU + 校正后货源链接 + 校正后规格
  -> 查商品SKU基础表
      -> 匹配到唯一商品SKU：平台SKU映射到商品SKU
      -> 未匹配：创建商品SKU，再映射
      -> 匹配多个：异常
  -> 销售参数写入平台SKU映射关系
```

### 4.3 同款多件流程

```text
输入平台SKU + 校正后货源链接 + 校正后规格 + 销售数量N
  -> 查/建商品SKU，商品SKU代表单件
  -> 查/建组合SKU
  -> 组合SKU明细 = 商品SKU x N
  -> 平台SKU映射到组合SKU
  -> 销售参数写入平台SKU映射关系
```

### 4.4 多商品套装流程

```text
输入平台SKU + 多个货源明细
  -> 每个货源明细查/建商品SKU
  -> 查/建组合SKU
  -> 组合SKU明细 = 多个 商品SKU x 数量
  -> 平台SKU映射到组合SKU
  -> 销售参数写入平台SKU映射关系
```

### 4.5 1688 采购配对流程

```text
商品SKU
  -> 绑定 1688链接 + 1688规格
  -> 可维护多个供应商
  -> 默认货源用于采购建议
```

组合 SKU 不直接做 1688 采购配对。

## 5. 输出设计

后续需要适配店小秘导入模板，输出至少拆成以下几类。

### 5.1 商品 SKU 新增/更新表

用于导入店小秘商品管理。

### 5.2 组合 SKU 新增/更新表

用于导入店小秘组合 SKU。

### 5.3 平台 SKU 配对表

用于导入店小秘平台 SKU 配对。

目标可能是：

```text
商品SKU
组合SKU
```

### 5.4 1688 采购配对表

用于维护商品 SKU 与 1688 货源规格关系。

## 6. 异常处理原则

工具必须支持持续运行。

```text
正常行继续处理
异常行跳过并输出异常表
异常行修正后可放入下一批继续处理
```

异常类型初稿：

```text
平台SKU为空
销售单元类型无法判断
货源链接清洗失败
规格为空
商品SKU匹配到多个
组合SKU明细为空
组合SKU明细重复
组合SKU编码无法生成
商品SKU编码无法生成
平台SKU已绑定不同目标
```

## 7. 与旧 POC 的边界

旧 POC 已归档：

```text
apps/_archive/sku_mapping_poc
apps/_archive/sku_source_update_poc
```

新工具不继承旧 POC 的业务假设。

可复用的只有：

```text
Excel 读取/导出经验
货源链接清洗经验
规格清洗经验
数据库连接经验
批次输出目录经验
异常行跳过经验
```

不能复用的旧假设：

```text
平台SKU一定映射商品SKU
商品SKU可以代表多件装
商品SKU可以代表销售组合
数量参与商品SKU身份
```
