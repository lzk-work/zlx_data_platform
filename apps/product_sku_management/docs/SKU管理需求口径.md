# SKU管理需求口径

本文档面向业务和技术共同确认口径。本文描述库存计费重构后的当前实现口径，后续编码应以本文为目标规则。

## 1. 当前范围

第一版实现“已上架平台SKU补数据”流程，并增加一个显式“平台SKU映射更新”模式。

目标流程包含：

```text
读取平台SKU补充Excel
清洗货源链接
解析1688规格
按货源链接、规格、数量识别或创建商品SKU
按商品SKU组合规则必要时创建组合SKU
创建销售单元
维护平台SKU映射
按店小秘新增/更新拆分导出模板
记录批次、行日志、异常、导出计划、店小秘同步状态
支持试运行
支持显式更新模式下的平台SKU改绑
```

暂不实现：

```text
新开发竞品正向流程
飞书记录自动回写
淘宝/天猫商品ID深度校验
店小秘导入反馈自动解析
商品SKU多货源维护流程
商品SKU款式组自动归并
内部库存扣减和库存流水
```

## 2. 核心对象

商品SKU：

```text
代表一个可采购、可上传店小秘并参与库存计费的商品单位。
目标唯一身份是：清洗后货源链接 + 去掉数量后的规格文本 + 数量。
数量必须进入商品SKU身份。
```

组合SKU：

```text
代表一个销售组合。
组合SKU只用于商品SKU数量不超过3个的多商品组合。
组合SKU明细由商品SKU组成，目标口径下每个商品SKU在组合内数量均为1。
```

强制合包商品SKU：

```text
当一个平台SKU解析出超过3个商品SKU明细时，不生成组合SKU。
此时需要强制合为一个商品SKU，用于店小秘商品SKU上传、平台SKU映射和计费。
该商品SKU不是采购最小单位，采购辨识依赖数据库中的结构化明细。
不单独新建强制合包主表，直接作为 product_sku 的一种类型保存。
```

销售单元：

```text
承接平台SKU侧的销售产品信息。
销售单元不等于商品SKU，也不等于组合SKU。
它保存平台输入中的主图、长宽高、总采购价、总重量、属性、报关名等销售侧信息，并指向商品SKU或组合SKU。
当多产品明细超过3个商品SKU时，目标口径下不创建组合SKU，而是强制合为一个商品SKU承接，并加备注给采购辨识。
```

商品SKU和销售单元尺寸关系：

```text
当商品SKU直接承接平台SKU销售单元时，product_sku 也保存长宽高，并标记 is_direct_sales_unit = true。
当商品SKU只是组合SKU成员时，商品SKU长宽高可以为空。
同一个商品SKU可以既直接销售，又作为组合SKU成员；作为组合成员出现时不能清空它已有的长宽高。
组合SKU的长宽高仍来自对应销售单元输入，不由成员商品SKU推导。
```

平台SKU：

```text
平台或店铺侧已有的SKU编码。
系统通过 platform_sku_mapping 记录平台SKU当前绑定到哪个商品SKU或组合SKU。
```

平台SKU配对关系：

```text
以商品SKU或组合SKU为目标，维护该目标当前对应的完整平台SKU集合。
店小秘更新时需要导出完整集合，不只导出新增平台SKU。
```

内部库存基础货品：

```text
后续内部库存管理可以按 货源链接 + 规格 归并。
它是数据库内部库存口径，不直接上传店小秘。
店小秘商品SKU按 货源链接 + 规格 + 数量 生成。
内部库存基础货品可从商品SKU表提取 source_url + spec 得到。
```

## 3. 商品SKU身份规则

商品SKU身份由三部分决定：

```text
清洗后货源链接 + 去掉数量后的规格文本 + 数量
```

数量必须进入商品SKU身份。

普通商品SKU唯一键：

```text
source_url + spec + quantity
```

例如：

```text
https://detail.1688.com/offer/755896330395.html
红色||XL||1
```

商品SKU身份是：

```text
source_url = https://detail.1688.com/offer/755896330395.html
spec = 红色||XL
quantity = 1
```

如果数量不同，需要生成不同商品SKU。例如：

```text
红色||XL||1
红色||XL||3
```

两者是不同商品SKU。

调整原因：库存和费用不是只按采购最小单位计算。产品数量超过3个会额外收费；如果把3个一组定义为一个商品SKU，店小秘按商品SKU数量计费时更符合业务成本口径。

店小秘商品SKU和内部库存基础货品的关系：

```text
内部库存基础货品 = source_url + spec
店小秘商品SKU = source_url + spec + quantity
```

示例：

```text
内部库存基础货品:
https://detail.1688.com/offer/755896330395.html + 红色||XL

店小秘商品SKU:
https://detail.1688.com/offer/755896330395.html + 红色||XL + 1
https://detail.1688.com/offer/755896330395.html + 红色||XL + 3
```

后续做内部库存时，可以从已生成的商品SKU提取库存基础货品，并建立商品SKU到库存基础货品的数量关系。

强制合包商品SKU唯一键：

```text
所有明细的 source_url + spec + quantity 结构化集合
```

生成规则：

```text
1. 先清洗每个货源链接。
2. 每个明细解析为 source_url、spec、quantity。
3. 按 source_url、spec、quantity 排序。
4. 拼接后生成 package_fingerprint。
5. package_fingerprint 相同则复用同一个强制合包商品SKU。
```

不建议直接使用录入的货源规格原文做唯一键，因为括号中英文、空格、明细顺序变化都会造成重复录入。

建议在 `product_sku` 中增加字段承接该口径：

```text
quantity
product_sku_type
package_fingerprint
package_details_json
length_cm
width_cm
height_cm
is_direct_sales_unit
```

普通商品SKU使用 `source_url + spec + quantity` 唯一识别；强制合包商品SKU使用 `package_fingerprint` 唯一识别。

## 4. 货源链接口径

1688链接：

```text
必须能识别 /offer/数字.html 或 /offer/数字.htm
统一清洗为 https://detail.1688.com/offer/{offer_id}.html
```

淘宝和天猫：

```text
第一版仅识别平台类型并保留原链接
不做商品ID归一和在线校验
```

其他链接：

```text
只要是完整 http/https 链接，可以保留为 other 平台
```

## 5. 1688规格口径

规格字段描述采购产品明细。每个产品最后一个 `||` 后面是采购数量，前面的内容是规格参数。

单个产品：

```text
规格参数1||规格参数2||数量
默认||1
```

多个产品：

```text
（规格参数1||数量）（规格参数2||数量）
(规格参数1||数量)(规格参数2||数量)
```

支持中英文括号混用，支持规格内容里包含括号。

只有整段都是连续外层括号分组时，才按多个产品拆分。普通规格中的括号不会触发拆分。

规格分隔符必须是英文半角双竖线：

```text
||
```

## 6. 销售单元和组合判定

目标口径仍保留销售单元类型，但组合判定规则调整为：

```text
单个产品明细，无论数量是多少 -> 生成或复用商品SKU，平台SKU直接映射商品SKU
多个产品明细，商品SKU数量 <= 3 -> 生成组合SKU，组合内每个商品SKU数量为1
多个产品明细，商品SKU数量 > 3 -> 不生成组合SKU，强制合为一个商品SKU承接，加备注给采购辨识
```

这里的“商品SKU数量”指一个平台SKU解析后涉及的商品SKU明细个数，不是单个规格里的采购数量。

销售单元的作用：

```text
销售单元记录输入平台SKU对应的销售侧信息。
销售单元会指向最终承接对象：商品SKU或组合SKU。
销售单元保存长宽高、主图、总采购价、总重量、属性、报关名、开发备注和处理批次。
销售单元不是店小秘导入对象本身，但它是平台SKU映射、反馈文件和后续追溯的中间层。
```

销售单元映射规则：

```text
单个产品明细 -> sales_unit.mapping_target_type = product_sku
<=3个商品SKU的多产品明细 -> sales_unit.mapping_target_type = bundle_sku
>3个商品SKU的多产品明细 -> sales_unit.mapping_target_type = product_sku，并在备注中保留采购辨识说明
```

商品SKU尺寸落库规则：

```text
单个产品明细 -> 商品SKU直接承接销售单元，写入长宽高，is_direct_sales_unit = true
<=3个商品SKU的多产品明细 -> 成员商品SKU长宽高可为空，不主动覆盖已有长宽高
>3个商品SKU的多产品明细 -> 强制合包商品SKU直接承接销售单元，写入长宽高，is_direct_sales_unit = true
```

示例：

```text
红色||XL||3
=> 一个商品SKU，数量3进入商品SKU身份，不创建组合SKU

（红色||XL||1）（蓝色||L||1）
=> 两个商品SKU，创建组合SKU，每个商品SKU*1

（A||1）（B||1）（C||1）（D||1）
=> 四个商品SKU明细，不创建组合SKU，强制合为一个商品SKU，平台SKU映射到该商品SKU，备注保留原始采购明细
```

## 7. 组合SKU口径

组合SKU唯一键是商品SKU组合。

组合指纹生成时会按商品SKU排序：

```text
商品SKU1*1|商品SKU2*1|商品SKU3*1
```

目标口径下，组合SKU明细里的数量固定为1。数量已经进入商品SKU身份，不再作为组合明细数量参与身份判断。

因此同一组商品SKU，即使输入顺序不同，也会复用同一个组合SKU。

组合SKU只用于不超过3个商品SKU的多产品组合。超过3个商品SKU时不创建组合SKU。

超过3个商品SKU时的强制合包口径：

```text
系统不生成组合SKU。
系统生成或复用一个强制合包商品SKU。
平台SKU映射到该强制合包商品SKU。
强制合包商品SKU用结构化明细 package_fingerprint 去重，避免后续重复录入。
店小秘备注只写原备注和“强制合并”标记；原始货源链接、原始规格、解析后明细保留在 package_details_json，便于采购辨识和后续内部库存提取。
强制合包商品SKU导出店小秘时，来源URL来自全部明细货源链接，去重后用换行拼接。
```

组合SKU导出店小秘时：

```text
每个明细行都填写 *组合sku
首行填写组合名称、主图、备注、报关名、申报重量、申报金额、来源URL、长宽高、危险运输品
来源URL来自组合内所有商品SKU的 source_url，去重后用换行拼接
长宽高来自销售单元输入
```

## 8. 产品属性口径

输入字段 `属性` 必填，目前只支持：

```text
普货
带电
敏感
```

店小秘危险运输品编码：

```text
普货 -> 0
带电 -> 1
敏感 -> 2
```

商品SKU、组合SKU、销售单元都会保存当前输入的属性。已有商品SKU或组合SKU再次被处理时，会用最新输入覆盖属性字段。

## 9. 中文名称口径

商品SKU中文名称：

```text
数量为1：规格参数1，规格参数2---数量1
数量大于1：N个/组，规格参数1，规格参数2---数量N
```

商品SKU中文名称中的数量使用商品SKU身份里的数量。

示例：

```text
红色，XL---数量1
3个/组，红色，XL---数量3
```

组合SKU中文名称：

```text
总件数 个/组，明细1，明细2...
```

示例：

```text
3 个/组，红色，XL---数量2，蓝色，L---数量1
```

## 10. 价格重量口径

货源采购价和重量按货源组填写。

商品SKU参考值：

```text
单个产品明细时，采购价和重量对应这个商品SKU身份数量。
多产品明细时，每个商品SKU参考值来自对应明细或货源组拆分规则，后续编码时需要明确计算公式。
```

销售单元和组合SKU总值：

```text
按输入平台SKU对应的采购明细总值计算
```

金额使用 Decimal 计算，避免价格相关字段使用浮点误差。数据库当前保留 `numeric(18, 4)`，导出时按模板写入。

待编码确认点：

```text
多产品在同一个货源组里共用一个采购价和重量时，是否继续按组内总件数均摊到各商品SKU。
如果业务可以按每个明细填写独立采购价和重量，需要扩展输入表结构。
```

## 11. 新增、更新、跳过口径

店小秘同步状态由 `sku_mgmt.dianxiaomi_sync_state` 维护。

判定规则：

```text
没有确认哈希 -> create
有确认哈希，但当前内容哈希不同 -> update
有确认哈希，且当前内容哈希相同 -> skip
```

导出模板按动作拆分：

```text
create -> *_create.xlsx
update -> *_update.xlsx
skip -> 不写店小秘模板
```

店小秘上传成功后，需要执行批次确认SQL，把 `last_export_hash` 固化为 `last_confirmed_hash`。

## 12. 平台SKU映射口径

同一个平台SKU再次出现，且映射目标不变：

```text
幂等处理，不报错。
平台配对是否导出取决于完整平台SKU集合是否变化。
```

同一个平台SKU新增到已有商品SKU或组合SKU：

```text
系统内部保存完整映射集合。
店小秘平台配对模板导出完整集合。
如果该目标已确认过，则导出 update。
```

同一个平台SKU改绑到不同目标：

```text
普通补充模式报异常：平台SKU已绑定不同映射目标。
显式更新模式允许改绑。
```

运行模式：

```text
supplement 普通补充模式：
    用于历史出单、日常补充和新增平台SKU。
    已绑定平台SKU如果解析出不同目标，直接报异常，不改库。

update 显式更新模式：
    用于业务确认后的平台SKU映射变更。
    输入格式与普通补充模式相同。
    允许平台SKU从旧商品SKU切到新商品SKU、从商品SKU切到组合SKU、从组合SKU切到商品SKU。
```

显式更新模式的数据处理规则：

```text
1. 按输入行重新解析货源链接、规格和数量。
2. 生成或复用新的商品SKU、组合SKU或强制合包商品SKU。
3. 查询该平台SKU当前已有映射。
4. 如果旧目标与新目标一致，按幂等处理。
5. 如果旧目标与新目标不同，更新 platform_sku_mapping 到新目标。
6. 旧商品SKU、旧组合SKU不删除，保留历史订单、库存和追溯痕迹。
7. 新生成的商品SKU或组合SKU按店小秘确认状态导出 create 或 update。
8. 平台SKU配对需要同时重算旧目标和新目标：
   旧目标导出移除该平台SKU后的完整平台SKU集合；
   新目标导出加入该平台SKU后的完整平台SKU集合。
```

从商品SKU变为组合SKU示例：

```text
原状态：
平台SKU A -> 商品SKU SS_1

更新输入解析为两个商品SKU：
商品SKU SS_2
商品SKU SS_3

处理结果：
生成或复用组合SKU ZH_1
platform_sku_mapping 更新为 平台SKU A -> 组合SKU ZH_1
平台配对更新导出：
    SS_1 的完整平台SKU集合中移除 A
    ZH_1 的完整平台SKU集合中加入 A
SS_1 不删除
```

## 13. 数据维护口径

允许人工直接维护数据库，但必须保持约束一致。

常见人工维护场景：

```text
补充 first_category_code 类目代号
修正 product_sku 或 bundle_sku 的属性、报关名等字段
确认店小秘上传成功后的同步状态
处理平台SKU改绑异常
```

不建议人工随意改：

```text
product_sku.product_sku
bundle_sku.bundle_sku
bundle_sku.detail_fingerprint
platform_sku_mapping.platform_sku
sku_code_counter.current_value
```

这些字段影响幂等识别、编码生成和店小秘同步判断。
