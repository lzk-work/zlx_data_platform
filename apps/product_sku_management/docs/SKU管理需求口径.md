# SKU管理需求口径

本文档面向业务和技术共同确认口径。所有规则以当前代码实现为准，不包含历史草案和未落地方案。

## 1. 当前范围

第一版只实现“已上架平台SKU补数据”流程。

已实现：

```text
读取平台SKU补充Excel
清洗货源链接
解析1688规格
识别或创建商品SKU
必要时创建组合SKU
创建销售单元
维护平台SKU映射
按店小秘新增/更新拆分导出模板
记录批次、行日志、异常、导出计划、店小秘同步状态
支持试运行
```

暂不实现：

```text
新开发竞品正向流程
飞书记录自动回写
淘宝/天猫商品ID深度校验
平台SKU自动改绑
店小秘导入反馈自动解析
商品SKU多货源维护流程
商品SKU款式组自动归并
```

## 2. 核心对象

商品SKU：

```text
代表一个可采购的基础商品。
当前唯一身份是：清洗后货源链接 + 去掉数量后的规格文本。
```

组合SKU：

```text
代表一个销售组合。
当平台SKU对应多个商品，或同一商品数量大于1时生成组合SKU。
组合SKU明细由商品SKU和数量组成。
```

销售单元：

```text
承接平台SKU侧的销售产品信息。
销售单元不等于商品SKU，也不等于组合SKU。
它保存平台输入中的主图、长宽高、总采购价、总重量、属性、报关名等销售侧信息，并指向商品SKU或组合SKU。
```

平台SKU：

```text
平台或店铺侧已有的SKU编码。
系统通过 platform_sku_mapping 记录平台SKU当前绑定到哪个商品SKU或组合SKU。
```

平台SKU配对关系：

```text
以商品SKU或组合SKU为目标，维护该目标当前对应的完整平台SKU集合。
店小秘更新时需要导出完整集合，不只导出新增平台SKU。
```

## 3. 商品SKU身份规则

商品SKU身份只看：

```text
清洗后货源链接 + 去掉数量后的规格文本
```

数量不进入商品SKU身份。

例如：

```text
https://detail.1688.com/offer/755896330395.html
红色||XL||1
```

商品SKU身份规格是：

```text
红色||XL
```

如果未来同一货源链接和同一规格对应不同商品SKU，就不符合当前设计理念。

## 4. 货源链接口径

1688链接：

```text
必须能识别 /offer/数字.html 或 /offer/数字.htm
统一清洗为 https://detail.1688.com/offer/{offer_id}.html
```

淘宝和天猫：

```text
第一版仅识别平台类型并保留原链接
不做商品ID归一和在线校验
```

其他链接：

```text
只要是完整 http/https 链接，可以保留为 other 平台
```

## 5. 1688规格口径

规格字段描述采购产品明细。每个产品最后一个 `||` 后面是采购数量，前面的内容是规格参数。

单个产品：

```text
规格参数1||规格参数2||数量
默认||1
```

多个产品：

```text
（规格参数1||数量）（规格参数2||数量）
(规格参数1||数量)(规格参数2||数量)
```

支持中英文括号混用，支持规格内容里包含括号。

只有整段都是连续外层括号分组时，才按多个产品拆分。普通规格中的括号不会触发拆分。

规格分隔符必须是英文半角双竖线：

```text
||
```

## 6. 销售单元类型

当前代码输出三种销售单元类型：

```text
single_product
same_product_multi_qty
multi_product_set
```

判定规则：

```text
单个商品，数量为1 -> single_product，不创建组合SKU
单个商品，数量大于1 -> same_product_multi_qty，创建组合SKU
多个商品明细 -> multi_product_set，创建组合SKU
```

## 7. 组合SKU口径

组合SKU由商品SKU和数量明细决定。

组合指纹生成时会按商品SKU排序：

```text
商品SKU1*数量|商品SKU2*数量
```

因此同一组商品SKU和数量，即使输入顺序不同，也会复用同一个组合SKU。

组合SKU导出店小秘时：

```text
每个明细行都填写 *组合sku
首行填写组合名称、主图、备注、报关名、申报重量、申报金额、来源URL、长宽高、危险运输品
来源URL来自组合内所有商品SKU的 source_url，去重后用换行拼接
长宽高来自销售单元输入
```

## 8. 产品属性口径

输入字段 `属性` 必填，目前只支持：

```text
普货
带电
敏感
```

店小秘危险运输品编码：

```text
普货 -> 0
带电 -> 1
敏感 -> 2
```

商品SKU、组合SKU、销售单元都会保存当前输入的属性。已有商品SKU或组合SKU再次被处理时，会用最新输入覆盖属性字段。

## 9. 中文名称口径

商品SKU中文名称：

```text
规格参数1，规格参数2---数量1
```

商品SKU固定显示数量1，因为数量不属于商品SKU身份。

组合SKU中文名称：

```text
总件数 个/组，明细1，明细2...
```

示例：

```text
3 个/组，红色，XL---数量2，蓝色，L---数量1
```

## 10. 价格重量口径

货源采购价和重量按货源组填写。

商品SKU参考值：

```text
货源组采购价 / 货源组总件数
货源组重量kg * 1000 / 货源组总件数
```

销售单元和组合SKU总值：

```text
按货源组去重后累加采购价和重量
```

金额使用 Decimal 计算，避免价格相关字段使用浮点误差。数据库当前保留 `numeric(18, 4)`，导出时按模板写入。

## 11. 新增、更新、跳过口径

店小秘同步状态由 `sku_mgmt.dianxiaomi_sync_state` 维护。

判定规则：

```text
没有确认哈希 -> create
有确认哈希，但当前内容哈希不同 -> update
有确认哈希，且当前内容哈希相同 -> skip
```

导出模板按动作拆分：

```text
create -> *_create.xlsx
update -> *_update.xlsx
skip -> 不写店小秘模板
```

店小秘上传成功后，需要执行批次确认SQL，把 `last_export_hash` 固化为 `last_confirmed_hash`。

## 12. 平台SKU映射口径

同一个平台SKU再次出现，且映射目标不变：

```text
幂等处理，不报错。
平台配对是否导出取决于完整平台SKU集合是否变化。
```

同一个平台SKU新增到已有商品SKU或组合SKU：

```text
系统内部保存完整映射集合。
店小秘平台配对模板导出完整集合。
如果该目标已确认过，则导出 update。
```

同一个平台SKU改绑到不同目标：

```text
当前版本报异常：平台SKU已绑定不同映射目标。
不自动解绑旧目标，也不自动绑定新目标。
```

## 13. 数据维护口径

允许人工直接维护数据库，但必须保持约束一致。

常见人工维护场景：

```text
补充 first_category_code 类目代号
修正 product_sku 或 bundle_sku 的属性、报关名等字段
确认店小秘上传成功后的同步状态
处理平台SKU改绑异常
```

不建议人工随意改：

```text
product_sku.product_sku
bundle_sku.bundle_sku
bundle_sku.detail_fingerprint
platform_sku_mapping.platform_sku
sku_code_counter.current_value
```

这些字段影响幂等识别、编码生成和店小秘同步判断。
