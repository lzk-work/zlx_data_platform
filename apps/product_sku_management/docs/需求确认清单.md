# 商品 SKU 管理需求确认清单

请按顺序确认。确认完成前不写业务代码。

## 1. 基础口径确认

1. 商品 SKU 是否固定为库存最小单位？

```text
商品SKU = 货源链接 + 规格 + 数量1
```

2. 平台 SKU 卖多件时，是否一律映射到组合 SKU？

示例：

```text
平台SKU A-2PCS
  -> 组合SKU A-2PCS
      -> 商品SKU A x2
```

3. 多商品套装是否一律映射到组合 SKU？

示例：

```text
平台SKU SET-A
  -> 组合SKU SET-A
      -> 商品SKU A x1
      -> 商品SKU B x1
```

4. 如果仓库已经预包装成独立库存的套装，是否允许作为普通商品 SKU？

可选口径：

```text
允许，预包装套装作为商品SKU
不允许，仍然作为组合SKU
按字段标记，由业务决定
```

## 2. 平台 SKU 唯一键确认

当前旧工具曾用：

```text
平台SKU
```

作为唯一键。

新工具是否仍然这样？

还是改为：

```text
平台渠道 + 店铺账号 + 平台SKU
```

建议确认为后者，更贴近店小秘和多店铺场景。

## 3. 字段归属确认

商品 SKU 是否只保留库存/采购身份字段？

建议商品 SKU 表只保留：

```text
商品SKU
货源链接
规格
货源图片链接
采购价
供应商
一级类目
类目代号
备注
```

以下字段是否全部放到平台 SKU 映射关系层？

```text
销售标题
销售图片
销售数量
重量/g
长/cm
宽/cm
高/cm
颜色
材质
中文报关名
英文报关名
销售备注
```

当前建议：是。

原因：

```text
商品SKU不是销售单元。
同一个商品SKU可能在不同平台、不同店铺、不同平台SKU下使用不同销售参数。
```

## 4. 输入表确认

新工具第一版需要支持哪些输入模式？

建议拆成三类：

```text
单品平台SKU输入表
同款多件平台SKU输入表
多商品套装平台SKU输入表
```

或者统一一张输入表，通过字段区分：

```text
销售单元类型
平台SKU
平台渠道
店铺账号
货源明细
销售数量
```

需要你确认：

```text
用一张统一输入表？
还是按单品/同款多件/多商品套装拆多个输入表？
```

## 5. 组合 SKU 编码规则确认

商品 SKU 已有编码规则要重审。

组合 SKU 编码需要确认。

可选方案：

```text
方案A：系统生成，格式 BUNDLE_YYMMDD_序号
方案B：基于子商品SKU生成，例如 商品SKU-2PCS
方案C：直接使用平台SKU作为组合SKU
方案D：业务输入组合SKU，系统只校验
```

建议：

```text
同款多件：商品SKU + 数量后缀
多商品套装：系统生成或业务输入
```

## 6. 商品 SKU 编码规则确认

旧规则：

```text
一级类目编码_YYMMDD_当日递增序号
```

新工具是否继续使用？

需要确认：

```text
商品SKU仍用旧规则？
组合SKU用新规则？
是否要适配店小秘 SKU 字符限制？
```

## 7. 1688 采购配对确认

一个商品 SKU 是否允许多个 1688 货源？

建议允许：

```text
商品SKU
  -> 默认货源
  -> 备用货源1
  -> 备用货源2
```

需要确认：

```text
第一版是否只维护默认货源？
还是直接支持多个货源？
```

## 8. 店小秘导入输出确认

第一版要输出哪些店小秘模板？

建议至少：

```text
商品SKU导入表
组合SKU导入表
平台SKU配对表
1688采购配对表
异常待处理表
处理日志表
```

需要你提供或确认店小秘模板字段。

## 9. 数据库表确认

新工具是否直接新建数据库表？

建议新建，不覆盖旧 `product_source`：

```text
product_sku
bundle_sku
bundle_sku_item
platform_sku_mapping
product_sku_purchase_source
```

需要确认：

```text
旧 product_source 是否迁移到 product_sku？
还是先新建干净表，从 0 开始？
```

## 10. 历史数据处理确认

旧数据里可能存在商品 SKU 代表多件装或套装。

需要确认迁移策略：

```text
直接废弃旧状态，从新输入开始
扫描旧库，拆分出最小商品SKU和组合SKU
只迁移确定为单品的 SKU，组合类人工处理
```

## 11. 第一版范围确认

建议第一版只做：

```text
读取输入 Excel
识别单品/组合
查/建商品SKU
查/建组合SKU
生成平台SKU映射
生成店小秘导入表
输出异常表
dry-run
正式写库
```

暂不做：

```text
店小秘 API 直连
ERP API 直连
飞书录入
库存同步
订单自动拉取
采购单自动生成
```

请确认第一版范围。
