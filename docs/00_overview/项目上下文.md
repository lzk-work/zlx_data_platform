# 项目上下文

## 公司背景

- 公司类型：跨境电商初创公司。
- 公司规模：约 10-20 人。
- 当前职责：负责数据中台、数据管理、自动化流程数据支持与数据入库。
- 成长目标：从执行型数据人员逐步向数据中台经理发展。

## 当前中台定位

数据中台不是单个脚本、单张报表或单次表格处理，而是围绕业务域、数据资产、流程闭环、标准化、可复用能力、权限与治理持续建设的一套工作体系。

当前阶段优先级：

1. 梳理业务流程和字段。
2. 用飞书多维表格承接业务录入。
3. 通过 API 将数据校验入库。
4. 通过数据库驱动状态流转和下游写回。
5. 将已完成、已校验、已标准化的数据增量同步到数据仓库。
6. 在数据仓库内引入 dbt 分层建模。

## 分库存储原则

当前整体数据架构采用“来源业务库”和“数据仓库库”分离的思路。

```text
飞书录入库
  负责飞书读取、校验、标准入库、状态回写、下游分发。

抓取/采集库
  负责影刀抓取、Python 抓取、平台采集、采集任务状态。

数据仓库库
  负责接收各来源已处理数据，并由 dbt 进行分层建模。
```

来源库不直接承担分析建模职责，数据仓库也不承担业务录入和流程回写职责。

统一数据流：

```text
来源业务库
  -> 按 updated_at 增量抽取已完成数据
  -> 写入数据仓库 ods/stg
  -> dbt 建模
  -> dwd/dim/dws/ads
```

## 代码注释约定

当前项目面向长期维护，不只服务一次性脚本。代码注释统一采用中文，方便业务和数据侧共同理解。

推荐注释范围：

- 模块注释：说明这个文件负责什么，不负责什么。
- 类注释：说明这个类在系统里的角色和边界。
- 函数注释：说明函数作用、关键参数、返回结果和重要注意事项。
- 复杂逻辑注释：解释为什么这样处理，尤其是鉴权、幂等、重试、事务、状态流转、字段映射等逻辑。

不推荐的注释：

- 不逐行翻译代码。
- 不写“给变量赋值”“调用函数”这类低价值注释。
- 不在注释里写真实密钥、真实客户数据、真实业务敏感信息。

函数注释建议格式：

```python
def example_function(arg1: str, arg2: int) -> dict:
    """说明函数做什么。

    参数：
        arg1: 参数含义。
        arg2: 参数含义。

    返回：
        返回值含义。

    注意：
        有必要时说明幂等、重试、异常、外部副作用等。
    """
```

原则：

```text
注释解释意图和边界，代码表达具体步骤。
```
