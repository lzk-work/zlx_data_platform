# 飞书节点管理骨架设计

## 定位

正式开发从节点管理骨架开始。

目标不是复制多个 POC 脚本，而是形成统一模式：

```text
一个飞书录入表 = 一个录入节点
一个录入节点 = 一个节点目录 + 一组三件套配置 + 一个标准业务表
```

后续新增节点时，优先新增配置和标准表，不重复写一套流程代码。

## 当前落地范围

当前已落地第一个单节点样例：

```text
configs/feishu_nodes/product_intake_poc/
  node.yaml
  table_mapping.yaml
  writeback.yaml
  distribution.yaml
```

当前已落地 runner 骨架：

```text
apps/feishu_node_runner/
  src/config_loader.py
  src/main.py
```

当前 runner 先支持：

```text
发现节点
加载节点配置
校验节点配置一致性
打印节点摘要
dry-run 检查
```

暂不直接替换 POC 主流程。等骨架稳定后，再把 POC 的读取、入库、回写、分发能力迁入通用 runner。

## 节点目录

每个节点一个目录。

目录名建议等于 `node_code`：

```text
configs/feishu_nodes/{node_code}/
```

示例：

```text
configs/feishu_nodes/product_intake_poc/
configs/feishu_nodes/sourcing/
configs/feishu_nodes/listing/
```

## node.yaml

`node.yaml` 描述节点本身。

职责：

```text
节点是谁
来源飞书表在哪里
标准业务表是哪张
运行时允许哪些动作
```

示例：

```yaml
node_code: product_intake_poc
node_name: 产品录入POC节点
enabled: true

source:
  app_token: "来源飞书多维表格 app_token"
  table_id: "来源飞书数据表 table_id"
  view_id:

database:
  biz_table: biz.product_intake_poc
  ods_table: ods.feishu_product_intake_raw

run:
  batch_size: 100
  allow_writeback: true
  allow_distribution: true
  allow_execute_distribution_immediately: false
```

规则：

```text
node_code 必须和目录名保持一致。
node_code 必须和 table_mapping.yaml 的 table_code 保持一致。
node_code 必须和 writeback.yaml / distribution.yaml 的 source_table_code 保持一致。
source.app_token/table_id 是来源飞书表。
database.biz_table 是当前节点处理后的标准业务表。
```

## 三件套配置

每个节点都有三件套。

```text
table_mapping.yaml
  来源字段如何映射到内部字段、数据库物理列和动态 JSON。

writeback.yaml
  当前节点处理结果如何回写来源飞书表。

distribution.yaml
  当前节点处理完成后如何分发到一个或多个下游目标表。
```

注意：

```text
三件套属于某一个来源节点。
不是全项目共用一份三件套。
distribution.yaml 中的多个 targets 只代表当前节点的多个下游目标。
```

## Runner 命令

列出节点：

```powershell
python -m apps.feishu_node_runner.src.main --list
```

只列出启用节点：

```powershell
python -m apps.feishu_node_runner.src.main --list --enabled-only
```

检查单个节点配置：

```powershell
python -m apps.feishu_node_runner.src.main --node product_intake_poc --dry-run
```

指定配置根目录：

```powershell
python -m apps.feishu_node_runner.src.main --config-root configs\feishu_nodes --node product_intake_poc --dry-run
```

## 校验内容

当前配置校验包括：

```text
节点必备文件是否存在。
node.yaml 是否有 node_code、node_name、source、database。
table_mapping.yaml 的 table_code 是否等于 node_code。
writeback.yaml 的 source_table_code 是否等于 node_code。
distribution.yaml 的 source_table_code 是否等于 node_code。
字段映射是否有 feishu_field、target、type。
分发目标是否有 target_table_code、target.app_token、target.table_id。
分发目标 target_table_code 是否重复。
```

## 后续扩展

下一阶段可以在这个骨架上继续接入正式流程：

```text
1. 通用 FeishuNodeRunner
   按 node_code 执行读取、ODS upsert、biz upsert、回写、分发。

2. 通用节点 checkpoint
   每个节点维护 last_success_sync_at。

3. 通用 ODS 当前态表
   一条飞书记录一个稳定 ods_id。

4. 通用分发执行器
   从 flow.feishu_distribution_task 读取 pending 任务并写目标飞书表。

5. 多节点批量调度
   --all-enabled 按配置运行所有启用节点。
```

## 当前原则

```text
先把节点管理骨架做稳。
先保证单节点配置可加载、可校验、可解释。
再把 POC 的实际同步逻辑迁移到正式 runner。
```
