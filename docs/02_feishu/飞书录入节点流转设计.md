# 飞书录入节点流转设计

## 设计目标

这份文档抽象多个飞书多维表格之间的数据流转方式。

核心结论：

```text
一个飞书录入表 = 一个录入节点 intake node
一个录入节点处理完成后，可以分发到下一个或多个录入节点
```

后续不管有几个表，系统都按同一套模式运行：

```text
录入节点 1
  -> 原始数据入库
  -> 标准数据入库
  -> 回写来源飞书表
  -> 分发到录入节点 2

录入节点 2
  -> 原始数据入库
  -> 标准数据入库
  -> 回写来源飞书表
  -> 分发到录入节点 3

继续重复
```

这样正式开发时不需要为每张表单独写一套流程，只需要新增节点配置和必要的标准表。

正式节点管理骨架设计见：

```text
docs/02_feishu/飞书节点管理骨架设计.md
```

飞书录入节点属于“来源业务库”范畴，不直接由 dbt 管理。节点处理完成并形成标准业务数据后，再由数据工程任务按 `updated_at` 增量同步到数据仓库。

```text
飞书录入库
  -> 节点录入、校验、回写、分发
  -> 已完成标准数据
  -> 增量入仓
  -> 数据仓库 dbt 建模
```

## 核心概念

### 录入节点

录入节点是一个业务处理环节，对应一个飞书多维表格中的一张数据表。

例如：

```text
product_development_intake
  产品开发录入节点

sourcing_intake
  货源处理录入节点

listing_intake
  上架资料录入节点
```

每个节点负责自己的录入、校验、入库、回写和分发。

### 节点输入

节点输入来自飞书多维表格。

读取时只读取符合条件的记录，例如：

```text
开发状态 = 已完成
并且
同步状态 != 已入库
```

正式阶段建议使用增量条件：

```text
业务状态达到可处理条件
并且
飞书最后更新时间 >= 上次成功同步时间
```

来源飞书表建议增加“最后更新时间”自动字段，用于后续增量同步。
POC 当前先验证固定状态过滤，后续再在 POC 中继续验证基于更新时间的增量读取。

### 节点输出

每个节点有三类输出：

```text
1. 数据库 ODS 原始数据
2. 数据库 biz 标准业务数据
3. 飞书回写或下游分发
```

其中 ODS/BIZ/SYNC/FLOW 位于飞书录入数据库；进入数据仓库是后续 ELT 入仓任务的职责。

回写是更新当前来源飞书表。

分发是创建或更新其他目标飞书表。

这两件事必须分开设计。

## 单节点标准流程

每个录入节点都执行同一套标准流程：

```text
读取来源飞书记录
  -> upsert ODS 当前态 raw_payload
  -> 根据 mapping 映射字段
  -> 校验必填、类型、枚举和业务规则
  -> 校验通过后写入 biz 标准表
  -> 维护 sync 映射和 checkpoint
  -> 按 writeback 配置回写来源飞书表
  -> 按 distribution 配置创建下游分发任务
```

如果校验失败：

```text
保存 ODS 原始数据
  -> 不写入标准业务表，或仅写入错误暂存表
  -> 回写校验失败和错误信息
  -> 不创建下游分发任务
```

## 多节点流转

多个节点串联时，前一个节点的分发结果成为后一个节点的来源录入数据。

示例：

```text
产品开发录入表
  -> 数据库保存开发标准数据
  -> 回写产品开发表
  -> 分发到货源处理录入表

货源处理录入表
  -> 数据库保存货源标准数据
  -> 回写货源处理表
  -> 分发到上架资料录入表

上架资料录入表
  -> 数据库保存上架标准数据
  -> 回写上架资料表
  -> 分发到后续发布、图片、翻译或运营节点
```

节点之间不直接读对方的业务表来驱动飞书写入，而是通过分发任务承接。

推荐链路：

```text
上游 biz 标准表
  -> flow.feishu_distribution_task
  -> 目标飞书录入表
  -> 目标节点同步程序
  -> 下游 biz 标准表
```

## 三类配置

每个录入节点建议对应三类配置。

配置粒度是“每个来源录入节点一组三件套”，不是全项目只有一套：

```text
一个飞书来源录入表
  -> 一个 table_mapping.yaml
  -> 一个 writeback.yaml
  -> 一个 distribution.yaml
```

如果有多个飞书录入表，就有多组节点配置：

```text
configs/feishu_nodes/product_development/table_mapping.yaml
configs/feishu_nodes/product_development/writeback.yaml
configs/feishu_nodes/product_development/distribution.yaml

configs/feishu_nodes/sourcing/table_mapping.yaml
configs/feishu_nodes/sourcing/writeback.yaml
configs/feishu_nodes/sourcing/distribution.yaml

configs/feishu_nodes/listing/table_mapping.yaml
configs/feishu_nodes/listing/writeback.yaml
configs/feishu_nodes/listing/distribution.yaml
```

同一个 `distribution.yaml` 可以包含多个 `targets`，含义是“当前这个来源节点处理完成后，同时或按规则分发到多个目标节点”。它不是所有节点共用的全局分发表配置。

### 录入映射配置

文件示例：

```text
table_mapping.yaml
```

职责：

```text
来源飞书字段
  -> 内部标准字段
  -> 数据库存储位置
  -> 类型和校验规则
```

典型字段：

```yaml
table_code: product_development_intake

fields:
  product_name:
    feishu_field: "产品名称"
    target: column
    db_table: biz.product_development
    db_column: product_name
    required: true
    feishu_type: text
    db_type: text

  product_features:
    feishu_field: "产品特点"
    target: dynamic_attributes
    required: false
    feishu_type: text
    json_type: text
```

规则：

```text
target: column
  必须对应数据库真实物理列。

target: dynamic_attributes
  写入动态字段 JSON。

raw_payload
  不在 mapping 中配置，由 ODS 自动保存飞书原始整行。
```

### 回写配置

文件示例：

```text
writeback.yaml
```

职责：

```text
把当前节点处理结果回写到来源飞书表当前 record_id。
```

示例：

```yaml
source_table_code: product_development_intake

fields:
  db_intake_id:
    feishu_field: "中台录入ID"
    value_from: db_intake_id
    type: text

  validation_status:
    feishu_field: "校验状态"
    value_from: validation_status
    type: text

  validation_message:
    feishu_field: "校验结果"
    value_from: validation_message
    type: text

  sync_status:
    feishu_field: "同步状态"
    value_from: sync_status
    type: text
```

规则：

```text
回写只更新来源表。
回写必须按 feishu_record_id 定位。
主业务入库成功后，回写失败不回滚主业务数据。
回写失败应记录并允许重试。
```

### 分发配置

文件示例：

```text
distribution.yaml
```

职责：

```text
把当前节点已经处理完成的数据，分发到一个或多个目标录入节点。
```

示例：

```yaml
source_table_code: product_development_intake

targets:
  - target_table_code: sourcing_intake
    enabled: true
    action_type: create
    execute_immediately: false
    target:
      app_token: ""
      table_id: ""
    fields:
      product_name:
        feishu_field: "产品名称"
        value_from: column_fields.product_name

      source_url:
        feishu_field: "来源链接"
        value_from: column_fields.source_url

      product_features:
        feishu_field: "产品特点"
        value_from: dynamic_attributes.product_features
```

规则：

```text
分发不是回写。
分发目标可以是一个或多个飞书录入表。
目标飞书表 app_token/table_id 属于业务流转配置，放在 distribution.yaml。
.env 只保存自建应用凭证、数据库连接、本地路径等运行环境参数。
建议先创建分发任务，再由执行器写目标飞书表。
目标表写入失败不影响当前节点入库。
```

## 数据库职责

正式设计中，数据库按职责分层承接所有节点。

### ODS

保存飞书原始当前态。

推荐通用表：

```text
ods.feishu_bitable_record_raw
```

核心规则：

```text
一条飞书记录 = 一个稳定 ods_id
重复同步时 update raw_payload，不新增多条 ODS。
```

唯一键：

```text
feishu_app_token + feishu_table_id + feishu_record_id
```

### BIZ

保存每个节点处理后的标准业务数据。

示例：

```text
biz.product_development
biz.sourcing_task
biz.listing_material
```

规则：

```text
通用字段进入物理列。
动态字段进入 dynamic_attributes JSON。
每张 biz 表通过 ods_id 追溯来源飞书原始数据。
```

### SYNC

保存同步映射、checkpoint 和回写状态。

推荐职责：

```text
记录 feishu_record_id 与 ods_id、biz_id 的关系。
记录每个节点最近成功同步时间。
记录回写状态和错误信息。
```

### FLOW

保存节点之间的分发任务。

推荐表：

```text
flow.feishu_distribution_task
```

核心字段：

```text
source_table_code
source_record_id
source_ods_id
source_biz_id
target_table_code
target_app_token
target_table_id
target_record_id
payload
status
retry_count
error_message
```

## 状态设计

每个节点至少需要以下状态。

来源飞书表字段：

```text
校验状态
校验结果
同步状态
同步时间
中台录入ID
```

数据库状态：

```text
validation_status
validation_message
sync_status
writeback_status
distribution_status
```

分发任务状态：

```text
pending
processing
success
failed
skipped
```

建议规则：

```text
校验失败
  回写错误，不分发。

入库成功，回写失败
  业务数据保留，回写任务可重试。

入库成功，分发失败
  当前节点成功，下游分发任务可重试。

目标节点处理失败
  只影响目标节点，不反向回滚上游节点。
```

## 运行方式

正式程序可以抽象成统一执行器。

示例命令：

```powershell
python -m apps.feishu_intake_runner --node product_development
python -m apps.feishu_intake_runner --node sourcing
python -m apps.feishu_intake_runner --node listing
```

执行器根据节点编码读取配置：

```text
configs/feishu_nodes/product_development/table_mapping.yaml
configs/feishu_nodes/product_development/writeback.yaml
configs/feishu_nodes/product_development/distribution.yaml
```

也可以批量运行：

```powershell
python -m apps.feishu_intake_runner --all-enabled-nodes
```

## 开发边界

POC 阶段只需要验证：

```text
单节点读取
单节点入库
单节点回写
单节点分发到目标飞书测试表
```

正式开发阶段再建设：

```text
节点注册表
统一节点执行器
通用 ODS 当前态表
通用 checkpoint
回写任务重试
分发任务执行器
节点级监控和通知
```

## 设计原则

```text
配置驱动，不为每张表重复写流程。
回写和分发分离。
ODS 保存来源当前态，biz 保存标准业务态。
数据库 ID 负责长期关联，飞书 record_id 负责短期 API 定位。
上游节点成功不依赖下游节点成功。
失败可记录、可重试、可追踪。
```
