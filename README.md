# ZLX Data Platform

ZLX 跨境电商数据中台建设项目。

当前阶段目标不是一次性完成完整数仓，而是在完整架构内先验证最小闭环：飞书多维表格录入、API 拉取、字段校验、写入数据库、状态回写飞书。

## 当前建设原则

- 飞书多维表格作为业务录入与协作界面。
- 数据库作为数据存储、校验、流转和事实口径中心。
- API 同步程序负责飞书与数据库之间的数据通道。
- 先承接业务数据，再逐步治理、分层和指标化。
- POC 也必须放在长期架构内，避免后续迁移混乱。

## 顶层目录

```text
docs/        项目文档、业务蓝图、字段设计、流程设计
database/    数据库 DDL、迁移、种子数据、表结构设计
apps/        可运行应用或 POC 子项目
connectors/  外部系统连接器，如飞书、数据库
pipelines/   来源库到数据仓库的增量入仓、跨库同步、数据工程任务
dbt/         后续 dbt 分层模型
scripts/     临时工具、清洗脚本、表格处理脚本
configs/     配置模板与本地配置占位
tests/       集成测试与测试样例
deploy/      调度、部署、容器化相关
archive/     归档内容
```

## 当前优先 POC

`apps/feishu_intake_poc` 用于验证：

1. 读取飞书多维表格记录。
2. 将记录映射、校验后写入数据库。
3. 将数据库 ID、校验状态、错误信息回写到飞书原记录。

POC 专属说明文档统一放在：

```text
apps/feishu_intake_poc/docs/
```

## 命名约定

- 技术目录、代码包、数据库对象使用英文与下划线。
- 业务文档使用中文命名，方便直接从文件名判断内容。
- 飞书字段面向业务可用中文，系统配置中建立英文映射。
- 真实密钥、客户数据、Excel、图片、压缩包、IDE 配置和缓存不提交。
